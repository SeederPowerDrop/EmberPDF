# 열린 PDF 갤러리 — 2026-10-05

대상: **EmberPDF 0.9.0 (build 23) Developer Preview**. 현재 워크스페이스에서 읽던 문서를 페이지 모습으로 찾아 돌아가는 기능이다. [build 22 디자인 기록](EMBER-DESIGN-2026-10-05.md)과 [페이지 번역 기록](PAGE-TRANSLATION-2026-10-05.md)은 당시 결과로 보존한다.

## 사용법

1. 탭 막대의 격자 버튼 또는 **보기 → 열린 PDF 갤러리 (`⇧⌘G`)**를 연다.
2. 현재 워크스페이스의 열린 PDF마다 **현재 페이지 전체**를 확인한다. 표지로 고정하지 않으며 접힌 탭 그룹의 문서도 포함한다. 파일 이름으로 검색할 수 있다.
3. 카드를 누르면 해당 문서로 돌아간다. 닫기 버튼·`Esc`·`⇧⌘G`·`⌘W`는 갤러리만 닫는다.

카드는 문서 이름, 현재/전체 페이지 번호, 활성 문서와 미저장 편집 상태를 표시한다. 창 크기에 따라 열 수가 달라지는 전체 창 그리드이며 macOS 전체 화면에서도 같은 방식으로 사용한다. PDF 같이 보기 중에는 진입할 수 없다.

## 상태 보존과 미리보기

- 기존 활성 `WorkspaceView`와 탭 막대의 배치를 유지한 채 갤러리가 덮는다. 같은 탭으로 복귀할 때 PDFView를 다시 만들거나 페이지 이동을 요청하지 않아 읽기 위치·확대·패널 상태를 유지한다.
- 진입 전에 폼·인라인 편집을 문서 모델에 반영하고 진행 중인 스크롤 보정을 중단한 다음 뷰포트를 저장한다. 숨겨진 문서의 입력·접근성·문서 명령은 차단한다. 현재 검색 스캔은 취소하되 이미 수집한 검색 결과는 유지한다.
- 번역·AI 패널을 종료하는 집중 보기나 비활성화 경로를 갤러리 진입에 재사용하지 않는다. 다른 탭을 실제로 선택하면 기존 탭 전환 수명 규칙을 따른다.
- `PDFDocumentGalleryPreviewService`는 필요한 카드의 현재 페이지만 직렬로 렌더링한다. 로드된 PDF는 메모리의 편집 결과를 사용한다. 휴면 PDF는 별도의 임시 문서로 한 페이지만 읽고 해제하며, 탭을 활성화하거나 모든 문서를 재개하지 않는다.
- 서비스 캐시는 **최대 32개·24 MiB**, 개별 이미지 크기는 **최대 변 길이 1,200px·100만 픽셀**이다. 오래된 페이지·문서 revision은 대체하고 메모리 압박과 갤러리 종료 때 캐시를 비운다. 이 수치는 앱 전체 메모리 상한이 아니며 표시 중인 카드·PDFKit 자원은 별도다.
- 사라졌거나 잠긴 문서, 읽기 실패는 일반적인 미리보기 대체 표시로 처리한다. 갤러리 미리보기만으로 암호 입력을 요구하지 않으며 원본 파일에 쓰지 않는다. 휴면 원본이 렌더링 도중 바뀌면 결과를 사용하지 않는다.

## 범위와 한계

- 현재 워크스페이스의 문서 탐색용 화면이다. 모든 워크스페이스를 통합하거나 갤러리 안에서 편집·페이지 넘김·비교를 수행하지 않는다.
- 파일 이름 검색이며 PDF 본문 검색은 기존 문서 검색에서 사용한다.
- 페이지 전체를 축소하므로 작은 글자를 읽는 용도는 문서 화면으로 돌아가야 한다. 무거운 한 페이지의 PDFKit 그리기 자체는 중간 취소할 수 없어 완료 뒤 취소된 결과를 버린다.
- 잠긴 휴면 문서의 미리보기를 위해 암호를 보관하거나 우회하지 않는다. 실제 문서를 선택하면 기존 열기·암호·오류 처리를 따른다.

영구 테스트 범위는 갤러리 미리보기 8개, 별도 프로세스의 네이티브 검색 스크롤 7개, 메뉴·명령 라우팅·다중 문서·탭 메모리·탭 그룹·비교 구성·현지화 106개다. 임시 SwiftUI 화면 검사는 실제 갤러리를 1,300×900 밝음/어두움 이미지로 렌더링했고 8개 합성 문서 중 휴면 문서 6개를 그대로 유지했다. 화면 검사 도우미와 결과는 `work/ember-gallery-20261005`에 보존하며 임시 테스트 파일은 영구 테스트 대상에서 제거했다.

Downloads의 실제 PDF **40개·5,654,605,688바이트**로 각각 표지가 아닌 현재 페이지를 렌더링했다. 준비와 검증을 포함한 기록 시간은 약 **3.23초**, 상주 문서는 시작과 끝 모두 **1개**, 최대 캐시 기록은 **23.95 MiB·27개**, 샘플링한 최대 RSS는 **113.84 MiB**였다. 파일 크기·수정 시각·장치·inode와 탭 페이지·선택·확대·revision이 유지됐다. 이 수치는 별도 테스트 프로세스의 서비스 검사이며 GUI 응답 지연, 순간 최대 메모리, 원본 내용 해시 또는 장시간 안정성 측정은 아니다. PDFKit이 일반적인 CoreGraphics 진단 한 줄을 출력했으나 모든 40개 미리보기와 보존 검사가 통과했다.

실제 앱에서 접힌 그룹을 포함한 현재 워크스페이스 12개 미리보기를 확인했다. 처음 진입했을 때 Esc가 동작하지 않던 문제를 닫기 버튼의 네이티브 취소 단축키로 수정하고, 진입 직후와 검색 입력 중 모두 다시 확인했다. 전체 화면 진입은 메뉴의 ‘전체 화면 종료’ 상태까지 확인했으나 이후 화면 도구의 창 연결이 끊겨 정상 종료·재실행으로 복구했다. 전체 화면 전환을 반복하는 장시간 GUI 검증 완료로 보지는 않는다. 최종적으로 일반 창의 갤러리를 열어 두었다.

설치 전후 저장된 세션 비교에서 **워크스페이스 2개·탭 26개·그룹 2개**, 탭 구성·페이지·선택·활성 탭/워크스페이스가 보존됐다. 이전 build 22 앱, 세션과 설정 백업은 같은 작업 폴더에 보존했다.

# Windows XP 분위기의 EmberPDF 정보 창 — 2026-10-14

EmberPDF 0.9.0 build 65는 사용자가 첨부한 알맹Re·ZipLens 정보 창을 참고해 정보 화면을 새로 구성한다.

## 구성과 문구

파란 그라데이션 제목줄, 흰 제목, 빨간 닫기 버튼, 밝은 베이지 또는 어두운 회색 바탕, 입체적인 확인·라이선스 버튼을 사용한다. 기존 제작자 그림을 유지하며 제목줄을 잡아 창을 옮길 수 있다. 긴 번역은 본문을 스크롤해서 읽고 하단 버튼은 항상 사용할 수 있다.

구독제로 바뀐 유료 PDF 앱에서 기존 기능을 쓰지 못하게 된 경험, 바이브 코딩으로 시작한 이유, 분노가 잉걸불 같은 온기로 바뀐 이야기, 오랫동안 무료로 배포하고 싶다는 바람을 담았다. Obsidian에서 영감을 받은 플러그인 기능과 기본 디지털 도구를 사람과 AI 모두 자유롭게 쓰고 함께 배우기를 바라는 소프트웨어 기본권 취지도 소개한다. 맞춤법은 ‘잉걸불’·‘Obsidian’으로 다듬었고 `ERW FWS WRG`는 그대로 보존했다.

## 후원과 라이선스

기존 공개 후원 목적지는 알맹Re의 `Sources/ImageViewer/Support/AboutContent.swift`에서 확인했다. 해당 소스는 ZipLens와 공유하는 공개 목적지임을 명시한다.

- Buy Me a Coffee: `https://buymeacoffee.com/master_chief`
- Ko-fi: `https://ko-fi.com/seederpower`
- Bitcoin: `BC1QUEUAX3FJP77NZUKF732AEWVFE0YVS9ZPKUMLTV`

BlueWallet 카드는 공개 주소의 QR 코드와 주소 복사 버튼을 연다. QR은 표시된 주소에서 만든 `bitcoin:` URI를 인코딩하며, 복사는 사용자 클릭 때만 실행한다. 후원 여부에 따라 앱 기능이 달라지지 않는다고 안내한다. 지갑을 자동 실행하거나 송금하지 않는다.

사용 가이드는 앱의 기존 도움말 창을 연다. 오픈소스 라이선스 보기는 번들의 MPL-2.0·저작권 고지·PDFium 및 AI 응답 표시 구성 요소의 라이선스 원문을 로컬에서 읽는다. DEBUG 실행만 소스 폴더를 대체 경로로 사용한다. 이전 대용량 PDF 시험 기록은 하단 ‘최근 확인한 내용’에서 그대로 볼 수 있다.

## 검증

- 정보 창은 960×740pt이며 본문은 스크롤된다. 10개 언어와 밝은·어두운 화면 조합 20개를 AppKit 호스트에서 렌더링했다. 한국어·영어·독일어·프랑스어·아랍어의 배치, 대비, RTL 방향을 눈으로 확인했다. 긴 번역에서는 본문 아래 후원 영역까지 스크롤해야 하며 하단 버튼은 고정되어 있다.
- Bitcoin 후원 팝오버와 라이선스 창도 밝은·어두운 화면 4개를 렌더링했다. 생성한 QR을 Core Image로 다시 읽어 표시된 공개 주소의 `bitcoin:` URI와 일치함을 검사했다.
- 프로젝트 MPL-2.0·저작권, KaTeX·Marked·DOMPurify·PDFium 라이선스 원문을 읽는 검사가 통과했다.
- `scripts/validate_project.sh` 통과: 0.9.0 build 65, macOS 14.0 이상, 10개 언어 키 일치 및 배포 리소스 검사.
- 직접 실행한 앱의 클릭·창 이동 확인은 Mac 잠금 상태로 진행하지 못했다. 렌더링 검사와 코드 검토 범위이며 후원 결제·송금은 수행하지 않았다.

관련 XCTest **29개 통과**: AboutContentTests 10개, AppMenuRegistrationTests 10개, HelpTutorialContentTests 9개. 도움말의 기존 문구가 ‘구분선’에서 ‘분할선’으로 바뀐 것을 반영하지 못한 검색 테스트 1개를 수정했다. 현재 ‘구분선’은 보기 도움말, ‘분할선’은 함께 보기 도움말을 찾는 것을 각각 확인한다. 도움말의 제품 동작이나 문구는 이번 작업에서 바꾸지 않았다.

로그와 화면은 `work/about65/`에 보관한다. 최종 테스트는 `verified-tests.log`, 최초 발견한 오래된 도움말 기댓값의 실패는 `final-tests.log`와 `help-isolated.log`, 패키징은 `package.log`에 기록되어 있다.

## build 66 문구 보완

사용자가 첫 두 문단에서 원래 감정이 퇴색했다고 지적하여, ‘화가 나서 바이브 코딩으로 만들었다’는 직접적인 표현을 복원했다. ‘잔잔한 온기’라는 추가 해석을 빼고, 마음이 잉걸불처럼 잔잔해진 흐름과 같은 일을 겪은 많은 사람들을 위해 오래 유지되는 앱이 되기를 기원한 뜻을 담았다. 한국어 기본 문구와 10개 언어의 첫 두 문단을 맞췄으며 디자인과 후원 동작은 동일하다.

>

## build 67 홈 화면 정보 버튼

`WelcomeView`의 플러그인 관리 옆에 ‘EmberPDF 정보’ 버튼을 추가했다. 기존 앱 수준의 `AboutContent.sceneID` 창을 열며, 여러 탭에서 눌러도 같은 정보 창을 사용한다. 첫 실행의 빈 작업 공간과 (+)로 만든 새 탭이 모두 이 홈 화면을 사용한다. PDF 세션이 복원되어 바로 문서가 표시되는 기존 동작은 유지한다.

기존 `about.title` 번역을 재사용하므로 10개 언어에서 현지화된다. `ViewThatFits`로 공간이 부족하면 플러그인·정보 버튼을 세로로 배치하고 버튼 글자는 자르지 않는다. 키보드와 접근성에서 인식되는 기본 Button이며 식별자는 `home-about`이다.

개발 빌드와 프로젝트 정적 검사가 통과했다. 한국어·프랑스어, 1420pt·820pt 너비, 밝은·어두운 모드의 실제 홈 뷰를 독립 AppKit 호스트에서 8개 렌더링했다. 화면·로그는 `work/home-about67/`에 보관한다. 화면 렌더링과 소스 경로 검토 범위이며 설치 앱을 직접 클릭한 검증은 아니다.

로컬 앱 `outputs/home-about-build67/EmberPDF.app`와 ZIP `outputs/home-about-build67/EmberPDF-0.9.0-macOS-arm64.zip` 생성 및 패키징 검증을 완료했다. ZIP SHA-256: `3de568260b6149fef9f88c337e78fdc83509a8b05cd25ac2f569cc612b5afaa9`.


## build 73 정보 창 정리와 제목줄 테두리 수정 — 2026-10-15

사용자 요청에 따라 하단 ‘최근 확인한 내용’ 버튼과 연결된 내부 시험 안내 화면을 제거했다. 사용하지 않는 `about.validation.*` 번역 키도 10개 언어에서 삭제했다. 라이선스 창은 기존 버튼에서 계속 열린다.

제목을 가로지르던 어두운 줄은 창 외곽 `Rectangle.stroke`가 macOS 제목줄의 안전 영역 경계에 그려진 것이었다. `.ignoresSafeArea()`를 외곽 테두리 뒤에 적용하여 내용과 테두리가 창 전체를 함께 채우도록 수정했다. 네이티브 제목줄 구분선도 명시적으로 숨긴다. 창 스타일이나 키보드·드래그·시트 수명 처리는 그대로다.

기존의 창 없는 `NSHostingView` 렌더링으로는 이 문제를 발견하지 못했다. 실제 `NSWindow`에 정보 화면을 붙인 회귀 검사를 추가하여 밝은·어두운 화면에서 제목줄 중앙 세로 방향의 RGB가 일정한지 확인한다. 수정 전 네이티브 이미지의 줄은 외곽 테두리와 같은 RGB였으며, 이 검사 기준을 넘는 22/255의 색상 차이가 있었다. 수정 후 두 화면 모두 통과했다.

- XCTest 11개 통과: 기존 AboutContentTests 10개와 네이티브 창 회귀 검사 1개.
- 10개 언어×밝은·어두운 화면, 후원·라이선스 패널, 네이티브 정보 창 렌더링을 확인했다.
- 프로젝트 정적 검사 통과: 0.9.0 build 73, 10개 언어 키 일치.
- 로그·렌더링: `work/about-cleanup/`. 최초 제한 환경에서는 Core Image QR 렌더링 1개가 실패했고, 시스템 그래픽에 접근할 수 있는 환경에서 11개 모두 통과했다.
- 실행 중인 사용자의 앱 대신 독립 테스트 창으로 검사했다.

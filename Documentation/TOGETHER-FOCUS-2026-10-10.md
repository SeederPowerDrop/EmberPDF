# 함께 보기 집중 모드와 종료 개선 — 2026-10-10

대상: EmberPDF 0.9.0 (build 41), macOS arm64. 앞선 build 40 기록과 체크섬은 변경하지 않는다.

## 변경

- 함께 보기 도구줄과 보기 메뉴에서 집중 모드를 제공한다. 탭·확장 영역·비교 도구줄·문서별 제목과 페이지 조절 영역을 접어 PDF 영역을 확장한다. 동일한 PDFView를 유지하며 배치와 동기 이동·고정 상태를 유지한다.
- 오른쪽 위 작은 버튼 또는 Esc로 집중 보기만 종료하고, 닫기 버튼으로 함께 보기를 종료한다. 고정된 문서는 핀 버튼을 유지한다. 집중 보기 전환의 레이아웃 애니메이션을 끄고 PDFKit 크기 재계산을 한 번에 수행한다.
- 읽기 전용 비교 뷰 종료 시 방문한 페이지 전체를 반복 검사하던 입력란 동기화를 생략한다. 일반 문서의 입력란 저장/실행 취소와 읽기 위치 캡처는 유지한다.
- 비교 문서 보호 해제 후 200 ms 뒤부터 정리 가능한 문서를 한 번에 하나씩 50 ms 간격으로 휴면시킨다. 정리 후보는 매번 재검사하고 새 비교 진입 시 예약을 취소한다. 실제 메모리 압력 신호에는 즉시 대응한다.

## 검증

- 최종 회귀 검사 **122개 통과**. 비교 배치·드래그·동기 이동·종료, 메모리 관리자, 네이티브 입력란 보존, 메뉴 명령 경계, 10개 언어 문자열을 검사했다. `work/together-build41/tests-final.log`.
- 64개 방문 페이지를 이용한 계측 테스트에서 비교 종료의 입력란 주석 접근은 기존 128회에서 0회로 줄었다. 일반 문서의 네이티브 입력란 변경 커밋과 실행 취소는 별도 검사로 유지됨을 확인했다.
- 새 메모리 정리 테스트 5개는 전환 지연/분할 처리, 활성·수정·닫힌 탭 재검사, 재진입 및 오래된 예약 취소, 긴급 메모리 압력, 창 종료 후 객체 해제를 검증했다.
- 별도 QA 앱과 자체 생성 PDF 5개로 실제 macOS UI 검증: A/B/C/D 4분할, 도구줄·보기 메뉴의 집중 보기, Esc로 집중 보기만 복귀, 집중 보기의 닫기 버튼과 일반 함께 보기 종료 버튼, 원래 E 탭 복귀 확인.
- A를 3페이지에 고정한 상태에서 집중 보기로 전환해 B를 스크롤하면 B/C/D만 5페이지로 이동했다. 집중 보기 전후와 앱 재실행 뒤 재진입에도 각 페이지·고정·4분할 배치를 유지했다.
- 최종 집중 보기에서 일반 도구줄·문서 제목/페이지 컨트롤은 접근성 트리에서도 제거된다. 작은 종료 버튼·고정 핀·분할선 조절만 유지한다.
- 정적 검증 통과, 언어 10개 parity 유지. 사용자의 실제 대용량 PDF 조합에 대한 전후 프레임 시간은 계측하지 않았다. 개별 PDFKit 해제·렌더 시간은 문서 복잡도에 따라 남을 수 있다.

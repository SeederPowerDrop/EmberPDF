## build 90의 편집·검색·저장 보완

검색어 입력 후 250ms 뒤 자동 검색하고 오래된 요청을 취소합니다. 인쇄된 쪽수와 실제 페이지 순서가 다르면 결과에 둘을 함께 표시합니다. 실행 중 언어를 바꾸면 기본 메뉴와 실행 취소 설명도 갱신하며 열린 문서와 편집 초안을 유지합니다.

밝고 균일한 배경의 스캔 본문과 일반 본문의 선택 편집·저장 후 재편집을 보완했습니다. 첫 편집의 불투명 배경과 클립 적용을 처리하고, 실제 원본에서 확인한 행별 복원 범위를 사용합니다. 저장 사본의 복원 정보는 해시와 실제 글자·그림 영역·폰트·그래픽 상태를 함께 검증합니다. 새 편집 폰트의 한자 의미 매핑을 보완해 일부 추출 엔진에서 글자 순서가 바뀌던 문제를 수정했습니다.

본문 교체 전에 원본 대응 정보를 확보해 링크 이름과 원래 인쇄·외관 속성을 유지합니다. 사용자가 명시적으로 수정한 주석은 원본 복원 대상에서 제외합니다. 구조가 있는 문서는 수정하지 않은 페이지의 태그 연결을 미리 확보하고, 본문 교체·실행 취소·다시 실행 후에도 유지합니다. 수정한 페이지의 오래된 본문과 잘못된 태그 연결을 다시 살리지 않습니다. 빈 양식의 계산 순서, 복구 사본의 주석·Popup 부재/null 구분과 대형 태그 PDF의 불필요한 탐색도 보완했습니다.

미리보기의 PNG 중간 변환을 제거하고 실제 비트맵 크기로 캐시 비용을 계산합니다. OCR 작업은 취소 가능한 전역 대기열로 고해상도 작업의 메모리 중첩을 제한합니다. 대형 저장은 분리된 문서 사본과 worker에서 처리하며 원본 소유권·권한·취소·외부 파일 변경 검사를 유지합니다. 앱의 RSS와 물리 메모리 점유량도 구분해 표시합니다.

이전 Source43 자동 회귀는 **2,584개 중 2,555 통과·29 조건부 건너뜀·실패 0개**입니다. 집중 735개도 모두 통과했습니다. 독일어·한자·영어·기술서 등 실제 PDF 5종에서 수정→저장→재열기→재편집→재저장을 통과했고, 저장 결과 10개 모두 사전에 선언한 편집 영역 밖 RGB 차이가 0입니다. 한자 문서의 두 저장은 PDFKit·PDFium·Poppler 세 방식의 텍스트 판독 5경로에서 순서를 보존했습니다.

원시 구조까지 포함한 본문 실문서의 엄격 종합 판정은 **0/5**로 기록합니다. 이미지·Catalog·폰트 직렬화 표현 차이와 원본 자체 진단을 시각·텍스트 보존 결과와 함께 보고서에 구분합니다. 이전 Source34 전체 폴더 기준 검사는 일반 PDF 373개 중 엄격 통과 327·실패 46이며, 암호화 PDF 9개는 읽기 전용 권한 정책 검사만 통과했습니다. 이 과거 수치를 최신 전체 문서 기능 통과로 합산하지 않습니다. 복잡하거나 손상된 PDF는 보존 근거가 부족하면 작업을 거부할 수 있습니다. 스캔 본문은 균일한 밝은 배경의 수평 글자 영역을 대상으로 하며, 문단·페이지 전체의 자동 재배치는 지원하지 않습니다.

이 패키지는 Apple Silicon용 Developer Preview입니다. Developer ID 서명·공증이 없으며 다운로드 후 최초 실행의 macOS 보안 확인은 설치 안내를 따릅니다.

## build 89의 첫 문서 열기 안정성 보완

사이드바의 일반·좁은 화면용 선택 컨트롤에 같은 언어 식별자를 부여해, 첫 PDF를 열 때 SwiftUI가 종료되는 오류를 수정합니다. 식별자에 화면용 대안을 함께 포함하며 언어 전환·문서·선택·편집 초안 보존을 유지합니다. 수정 전 실제 컨트롤의 최소 재현은 같은 종료를 일으켰고, 대안을 구분한 경우 5개 언어 전환과 5개 폭 조합 25회가 모두 통과했습니다. 실제 사이드바를 mount하는 회귀도 추가합니다.

build 88의 전체 자동 검사 통과 뒤 실제 앱에서 발견한 종료이므로, build 89는 새 실행 파일로 다시 검증합니다. 최종 실문서·실제 화면·설치 결과는 아직 진행 중이며 수정 전 후보 기록을 보존합니다.

## build 88의 실제 편집과 언어 전환 보완

스캔 본문의 글자 크기가 원래 줄의 기준선 간격보다 클 때, 적용 과정에서 기준선 간격을 글자 크기까지 늘리던 오류를 수정합니다. 원래 간격을 편집 화면과 저장 결과에 유지하며 선택 영역·페이지·의미상 행 수 보존 검사는 그대로 적용합니다. 독일어 184쪽에서 숫자 하나만 바꿔도 거절되던 실제 사례를 추가 회귀 대상으로 고정했습니다.

실행 중 언어를 변경하면 모드·사이드바 선택 버튼을 해당 언어로 다시 구성합니다. 문서·PDFView·작업공간과 편집 초안의 식별자는 유지합니다. 설치 안내와 릴리스 노트의 현재 버전·빌드가 앱 정보와 다르면 배포 검사를 거절하도록 보완합니다.

build 88은 자동 회귀·자원 검사를 통과했지만 실제 첫 문서 열기 종료로 배포하지 않았습니다. build 87의 자동 검사 통과 뒤 실제 화면에서 발견한 오류와 수정 전 기록은 후보 검증 기록에 보존합니다.

## build 87의 품질·자원 관리 개선

갤러리는 완성된 비트맵을 직접 전달해 미리보기마다 PNG로 압축하고 다시 푸는 단계를 제거합니다. 캐시 비용은 실제 행 크기와 높이로 계산하며, 문서 소유권·취소·파일 버전·권한 검사는 유지합니다.

여러 문서의 OCR 요청은 전역 대기열에서 순서대로 처리합니다. 대기는 스레드를 점유하지 않고 취소할 수 있으며, 실행 중인 네이티브 작업이 실제 종료된 뒤 다음 요청이 시작됩니다. 두 번째 요청의 대기시간이 늘어날 수 있지만 고해상도 OCR 작업의 메모리 중첩을 제한합니다.

리소스 모니터에 압축 메모리를 포함하는 프로세스 점유량을 RSS와 구분해 추가했습니다. 별도 작업 프로세스가 포함되지 않는다는 범위도 10개 언어로 안내합니다. 배포 검사기는 실제 네이티브 스트림 target과 QPDF 입력·라이선스·무결성을 검증합니다.

최종 검증은 진행 중입니다. 아래 build 86의 회귀·성능 수치는 이전 빌드의 이력이며 build 87 전체 통과를 뜻하지 않습니다. 일반 사용자 배포의 서명·공증·다운로드 첫 실행 여부는 별도 배포 gate입니다.

## build 86의 본문 적용·대형 문서 저장 개선

검색 결과가 남아 있는 상태에서 새로 드래그한 여러 줄 대신 이전 검색 단어만 편집기에 들어오던 문제를 고쳤습니다. 화면 갱신과 명시적인 검색 이동을 분리하고, 수동 드래그·편집 초안·언어 전환과 화면 재생성 때의 선택 소유권을 유지합니다.

본문 적용 중 같은 그림·글꼴 자원을 반복 인코딩하던 작업을 줄였습니다. 전체 책을 저장할 때는 원본 파일과 PDF 객체의 연결 및 필터·마스크가 확인된 이미지 스트림의 원래 압축 바이트를 보존합니다. 대형 접근성 태그의 빈 슬롯은 모든 항목을 검증하면서 한 번에 순회하고, 원본 문서·트리 연결이 입증되지 않으면 기존 검증 경로를 사용합니다. 취소·오래된 편집·새 미저장 입력 보호와 기존 구조 보존 검사는 유지합니다.

같은 Mac에서 고정한 build 85와 최종 build 86을 각 두 번 실행했습니다. 독일어 경기장 책 408쪽의 본문 적용은 **4.27~5.48초 → 1.10초**, 전체 저장은 **37.48~58.07초 → 1.40~1.44초**입니다. 357쪽 태그 문서의 전체 저장은 **56.72~59.44초 → 10.36~10.45초**입니다. 이는 AppKit 모델 통합 측정이며, 병렬 작업이 존재하는 호스트의 부하도 함께 기록했습니다. 실제 화면 클릭 시간이나 모든 PDF의 속도 보장은 아닙니다.

최종 소스 revision 3 입력 739개를 고정했습니다. 새 선택 회귀 5개는 기존 코드에서 모두 실패한 뒤 수정본에서 통과했습니다. 전체 회귀 2,149개는 2,129개 통과·조건부 검사 20개 제외·실패 0개이며, 집중 검사와 네이티브 경계 검사도 통과했습니다. 차단됐던 23개를 포함한 원본 30개 PDF의 병합·추출과 실제 비동기 저장 61개, 270개 페이지 픽셀 대조를 다시 통과했습니다. 설치한 앱에서 독일어·한자 OCR·한국어·대형 태그 문서 네 종류의 수정→저장→재열기→재편집→저장을 확인했고, 여덟 저장 결과의 독립 검사는 8/8 PASS입니다. 독일어 두 결과는 각각 408쪽 전체 대조에서 편집 영역 밖 차이 0픽셀입니다. 한국어↔영어 전환 중 초안 유지와 357쪽 저장 중 페이지 이동 응답도 확인했습니다. 기존 원본 24개·3개 작업공간·26개 탭·설정 보존을 대조한 뒤 build 86을 정상 실행했습니다.

## build 37의 PDF 비교 배치·이동

- 탭 막대의 **비교** 버튼과 화면 배치 메뉴에서 비교를 엽니다. 열린 PDF 중 원하는 2~4개를 선택합니다.

- 핀을 켠 PDF는 스크롤·페이지·확대를 고정합니다. 혼합 배치와 비율·고정 상태를 다음 실행에도 복원합니다.

- 앱 정보에 **HwattakPDF로 시작한 분노를 누구나 PDF를 편리하고 편안하게 다루도록 돕는 힘으로 바꾸고, 잉걸불처럼 오래 사용자 곁을 지키려 EmberPDF라는 이름을 지었다**는 이야기를 담았습니다. 시작 화면의 제작 계기 이스터에그도 유지합니다.
- **열린 PDF 갤러리**에서 PDF마다 읽던 페이지 전체를 카드로 봅니다. 접힌 그룹의 문서도 포함하며 카드 선택으로 읽던 문서에 복귀합니다. 탭 막대의 격자 버튼 또는 **보기 → 열린 PDF 갤러리 (`⇧⌘G`)**로 열고 `Esc`·`⇧⌘G`·`⌘W`로 닫습니다. 창 크기에 맞춰 열 수가 바뀌며 macOS 전체 화면에서도 사용합니다. PDF 같이 보기 중에는 사용할 수 없습니다. 구현 범위와 검증 상태는 [갤러리 기록](OPEN-PDF-GALLERY-2026-10-05.md)을 따릅니다.
- 작업 화면 전체를 따뜻한 숯빛·미색 표면과 절제된 앰버 강조색으로 통일했습니다. 활성 탭·썸네일·키보드 포커스는 얇고 분명하게 표시하고, 도구 버튼은 마우스를 올렸을 때 조용히 반응합니다. 집중 보기에는 이름을 붙여 찾기 쉽게 했으며, 홈과 정보 창도 같은 색상 체계를 사용합니다. 원본 색상 모드에서는 PDF 본문 색을 유지하며, 모든 읽기 색상에서 저장 데이터는 바꾸지 않습니다.
- Finder에서 PDF를 더블클릭하거나 “다음으로 열기”로 실행했을 때 창과 문서가 열리지 않던 문제에 대응했습니다. 앱 준비 전에 받은 요청을 보관하고 창 표시 뒤 처리하며, 중복 파일 요청과 대기 중 창 닫기·재연결도 처리합니다. [이슈 #1](https://github.com/SeederPowerDrop/HwattakPDF/issues/1)과 [수정 제안 PR #2](https://github.com/SeederPowerDrop/HwattakPDF/pull/2)를 제공한 **mattkjeon**님께 감사드립니다. 현재 소스에는 독립적으로 구현한 앱 수명 기준의 조정기를 사용하며 PR을 병합한 것으로 기록하지 않습니다.
- 앱 표시 이름·SwiftPM 패키지·실행 제품·배포 번들을 **EmberPDF**로 바꿨습니다. 내부 Swift 모듈·소스·테스트 경로는 `HwattakPDF`를 유지하며, 번들 ID `com.vibepdf.mac`과 기존 사용자 데이터·PDF 주석·플러그인의 저장 식별자도 호환성을 위해 유지합니다.
- 시작 화면 문구를 **“잉걸불처럼 오래도록, 든든한 PDF 도구.”**로 바꾸고 따뜻한 강조색을 적용했습니다. 제작 계기는 시작 화면에 상시 표시하지 않고 이름에 숨긴 이스터에그에서 볼 수 있습니다. **EmberPDF** 이름을 각 입력 간격 2초 이내로 5번 누르면 열리며, 키보드 버튼 조작과 VoiceOver의 별도 접근성 동작도 지원합니다.
- 온전한 종이를 아래의 잉걸불이 따뜻하게 비추는 **잉걸불** 아이콘을 새 기본 앱 아이콘으로 적용했습니다. **Ember** 제목은 선명하게, 본문은 은은한 활자 형태로 표현했습니다. Finder·Dock용 16–1024px 표현을 포함하며, **설정 → 앱 아이콘**에서도 선택할 수 있습니다. 기존에 직접 선택한 다른 아이콘 설정은 유지합니다.
- 설정에서 기본 PDF 앱 연결 상태를 확인하고 Finder의 연결 설정으로 이동할 수 있습니다. 앱의 남색·아이보리와 두 페이지 모양을 살린 PDF 전용 문서 아이콘을 추가했습니다.
- **설정(⌘,) → 화면 모드**, 또는 **보기 → 화면 모드**에서 라이트·다크·시스템 설정을 선택합니다. 선택은 다음 실행에도 유지되며 문서 작업공간과 보조 창에 함께 적용됩니다.
- 배경을 중립색으로 바꾸고 테두리·탭·도구줄의 무게를 줄였습니다. 홈은 **파일 열기와 최근 문서** 중심으로 정리했습니다. 한국어의 “PDF 비교”는 “PDF 같이 보기”로 표시합니다.
- 뷰어의 추가 도구는 필요할 때 펼치며, 편집·학습으로 전환하면 해당 도구가 나타납니다. 검색은 버튼이나 **⌘F**, 페이지 배치·맞춤은 보기 설정, 썸네일 묶음·크기는 페이지 패널의 작은 설정 메뉴에서 엽니다. 기능과 기존 메뉴·단축키 접근은 유지합니다.

### 읽기와 학습

- 메인 PDF에서 상하 스크롤 또는 좌우 넘김을 선택합니다. 좌우 넘김은 방향키·스와이프를 지원하며 여러 페이지 보기에서는 묶음 단위로 이동합니다.
- 보기 설정에서 **가로 폭 맞춤·세로 높이 맞춤**을 선택하고 문서별 선택을 복원합니다. 썸네일 패널에서도 방향키로 페이지를 탐색합니다.
- 페이지 패널을 넓히거나 높이면 썸네일도 함께 커집니다. 세로 패널의 폭과 가로 패널의 높이, 페이지 비율·회전을 반영하며 크기를 바꾸는 동안 기존 미리보기를 유지합니다. 1·2·4페이지 묶음 설정은 메인 PDF의 보기 방식과 별개이며, 썸네일 크기 슬라이더는 최대 **200%**까지 지원합니다.
- 1·2페이지 PDF 본문에서 검색 결과 위치를 스크롤바 눈금과 옅은 점선으로 표시합니다. 천천히 스크롤하다 가까운 결과에서 멈추면 작은 거리로 부드럽게 정렬합니다. 표시와 정렬은 PDF 파일을 수정하지 않으며, 빠른 스크롤·글자 선택·확대 중에는 자동 정렬하지 않습니다. 고정 페이지 보기의 눈금은 현재 펼침 범위이며, 비교 보기와 macOS 동작 줄이기에서는 위치 표시만 제공합니다.
- 방향키를 길게 누를 때 기본 반복 속도를 이전보다 **1.8배**, **Shift+방향키**는 이전 기본 대비 **4배**로 높였습니다. **설정 → PDF 보기 조작 → 방향키 이동 속도**에서 느리게·보통·빠르게를 선택합니다. **Option+방향키**는 기존 페이지 넘김 등 PDFKit 동작을 유지하며, 글자 입력·선택이나 주석 이동을 가로채지 않습니다.
- 하이라이트와 밑줄의 굵기를 따로 기억하고, 밑줄이 작은 글자를 덮는 문제와 표식 적용 후 남는 선택 표시를 수정했습니다. 도구 안에서 색상을 고르는 팔레트도 추가했습니다.
- 잘못된 글꼴 치수 때문에 선택 표시가 페이지를 덮는 PDF는 원문을 유지한 임시 선택용 페이지에서 치수를 보정합니다. 일반 드래그로 한 페이지의 글자를 따라 선택하고, 선택한 원문을 번역·복사에 사용합니다. 원본 PDF는 바꾸지 않습니다. 보정할 수 없는 페이지는 사각형 문자 인식으로 전환하며, **Option(⌥)을 누른 채 드래그**하면 직접 영역을 지정할 수 있습니다. 문자 인식 결과에는 오타가 있을 수 있습니다.
- 클릭하여 열고 검색하는 플러그인 목록을 제공하며, 메뉴를 고르는 도중 하위 메뉴가 닫히는 문제를 수정했습니다.
- 페이지 번역에서 문단별 결과를 검토하고 내보낼 수 있습니다. Apple 번역·사용자 설정 AI와 별도로 **로컬 언어팩**을 선택할 수 있으며, Argos 도우미는 사용자가 직접 실행합니다. 최초 설치·언어팩 준비에는 인터넷이 필요하고, 준비된 언어팩의 번역은 이 Mac에서 처리합니다. [설치 방법과 한계](LOCAL-TRANSLATION.md).

### PDF 만들기와 변환

- OCR 대상을 전체 페이지, 현재 페이지, 직접 입력한 페이지 번호·범위 중에서 선택합니다. 예를 들어 `1, 3-5, 8`을 입력하면 해당 페이지만 인식하고 나머지 페이지는 유지합니다. 적용·새 PDF 저장 모두 전체 문서에서 선택한 페이지만 반영하며, OCR 설명을 쉬운 표현으로 바꿨습니다.
- 로컬 OCR에서 현재 Mac이 지원하는 언어를 검색·선택하고 대상 PDF 이름·폴더·페이지 수를 확인합니다. 완료 후 현재 PDF에 실행 취소 가능한 편집으로 적용하거나, 원본 폴더에 `원본이름-ocr.pdf`를 기본값으로 새 PDF를 저장할 수 있습니다. 현재 PDF에 적용한 내용은 저장할 때 파일에 반영됩니다.
- 저장 창에서 선택한 파일에만 쓰기 권한이 있을 때 OCR 사본 저장이 실패하던 문제를 수정했습니다. 긴 한글 파일명도 처리하며, 저장 실패 시 실제 원인과 다시 저장할 수 있다는 안내를 표시합니다.
- OCR은 기존 텍스트가 있는 페이지도 기본적으로 다시 인식합니다. 재인식한 페이지의 잘못된 옛 텍스트는 새 결과로 교체하고, 검색되지 않는 글자가 보일 때 재인식 방법을 안내합니다. 기존 텍스트를 교체하는 페이지는 선택한 해상도의 이미지와 새 검색용 텍스트로 저장합니다.
- 이미지를 탭에서 열고, 여러 이미지·로컬 HTML·기존 PDF의 선택 페이지와 공백 페이지를 조립해 새 PDF를 만듭니다.
- PDF 만들기의 안정성 우선·속도 우선 선택, 예상 시간·용량, 한·영·일 OCR과 검색 가능한 텍스트 층, 인식 텍스트 복사·파일 저장을 제공합니다.
- PDF 각 페이지의 보이는 모양을 이미지로 담아 Word(`.docx`)·PowerPoint(`.pptx`)로 내보냅니다. 한 페이지씩 처리하며 진행률과 취소를 지원합니다.
- 이미지의 최초 PDF 저장, 같은 이미지의 중복 탭, 조립 도중 바뀐 원본 파일 처리와 비정상 Office 페이지 크기 검사를 보완했습니다.

### 복구와 플러그인

- **실행형 플러그인 SDK(schema 5)**를 추가했습니다. 개발자는 JavaScript로 자신의 명령·페이지/선택 이벤트·텍스트/목록/입력 UI를 만들고, 승인된 host API로 문서·검색·노트·읽기 색상·플러그인별 저장소를 조합합니다. [Reading Lab](../Examples/Plugins/ReadingLab.hwattakplugin/README.md)은 앱에 하드코딩되지 않은 페이지 분석 예제입니다.
- Script는 PDF 앱과 분리된 `EmberPluginWorker`에서 실행합니다. 코드 SHA-256, 제한된 JSON 연결, dispatch별 3초 watchdog과 중지/철회 수명 관리를 적용합니다. 임의 Node·파일·네트워크·DOM 권한을 상속하는 API는 제공하지 않습니다.
- **권한별 허용/철회와 안전 모드**를 추가했습니다. 업데이트 검토가 필요한 새 권한을 디스크 갱신만으로 승인하지 않으며, 기존 철회는 업데이트 후에도 유지합니다. 패키지 파일의 링크/FIFO 교체와 저장된 Markdown의 외부 편집 충돌도 검사합니다.
- 읽기 색상, Markdown 노트, 페이지 이미지 클립, 열린 문서 연관 검색, 기기 내 커서 번역을 호스트 패널 예제로 제공합니다. 기존 6개와 패널 5개, Reading Lab·Research Trail을 더한 **13개 기본 검토본**은 사용자가 골라 설치합니다. 커서 번역에는 macOS 15 이상이 필요합니다.

- **페이지 번역** 기본 플러그인을 추가했습니다. 현재 페이지의 그림과 배치를 배경으로 원문 위치에 번역문을 표시하며 원본/번역 전환, 확대 미리보기, 번역 페이지 PDF 사본 저장을 제공합니다. 원본 파일은 변경하지 않습니다. 번역문이 영역에 다 들어가지 않으면 번호를 표시하고 이어지는 페이지에 전체 번역을 담습니다. 텍스트 영역 배경과 복잡한 표·수식은 정확히 재현하지 못할 수 있으며, 스캔 페이지에는 먼저 OCR이 필요합니다. 기존 번역 도우미의 설치 manifest는 유지됩니다.

- 비암호화 문서의 확정된 편집을 로컬 복구 사본으로 보관합니다. **PDF → 작업 복구…**에서 별도 문서로 열 수 있으며, 설정에서 복구와 OCR 체크포인트를 관리합니다.
- 지연 썸네일과 대용량 탭 처리, OCR 뒤 복구 예약, 휴면 복구 탭 닫기, PDF 복사·지우개 권한 검사를 개선했습니다.
- 필압에 따라 굵기가 변하는 획과 저장 외형을 지원하고, 필압 주석이 있는 페이지를 추출할 때 종료되던 문제를 수정했습니다.
- 문서 명령 플러그인(schema 3)과 **⇧⌘P** 명령 팔레트를 추가했습니다. 번역 도우미·웹 브라우저에 더해 Study Markup·Tablet Tools·Reading Navigation 검토본을 포함합니다. 각 플러그인은 권한을 확인한 뒤 설치하며 자동 활성화되지 않습니다.

## 설치와 업데이트

1. `EmberPDF-0.9.0-macOS-arm64.zip`의 SHA-256 값을 함께 제공된 체크섬과 비교합니다.
2. 기존 앱을 사용 중이면 문서를 저장하고 EmberPDF 또는 이전 HwattakPDF를 종료합니다.
3. 압축을 풀어 `EmberPDF.app`을 응용 프로그램 폴더에 넣고 실행합니다.
4. 기본 PDF 앱으로 사용하려면 **설정 → 기본 PDF 앱 → Finder에서 연결 설정…**을 연 뒤 **정보 가져오기 → 다음으로 열기 → EmberPDF → 모두 변경**으로 연결합니다.

이전 이름의 HwattakPDF에서 업데이트했다면 EmberPDF 실행을 확인한 뒤 이전 `HwattakPDF.app`을 정리하세요. 번들 ID와 기존 설정·데이터 경로는 유지됩니다. 자세한 절차는 함께 제공되는 `INSTALL-macOS.txt`에 있습니다.

터미널에서는 다음과 같이 ZIP의 SHA-256을 확인할 수 있습니다.

```bash
shasum -a 256 EmberPDF-0.9.0-macOS-arm64.zip
```

이 빌드는 공증을 받지 않아 처음 실행할 때 macOS가 경고할 수 있습니다. 출처와 체크섬을 확인한 경우에만 앱을 한 번 열어 본 뒤 **시스템 설정 → 개인정보 보호 및 보안**의 실행 허용 절차를 선택하세요. 자세한 절차는 [Apple 공식 안내](https://support.apple.com/ko-kr/guide/mac-help/mh40616/mac)를 따릅니다.

## 검증과 알려진 한계

build 27은 관련 XCTest 139개(중복 제외)와 최종 helper의 프로토콜 smoke 7개가 통과했습니다. 설치 앱에서 SDK·페이지 이벤트·권한 철회·Return 명령 실행·Markdown 신규/기존 저장과 다시 열기·페이지 PNG 저장을 확인했습니다. 실행 범위와 배포 검증은 [플러그인 확장 플랫폼 기록](EXTENSIONS-2026-10-06.md), API는 [호스트/SDK 참조](PLUGIN-HOST-API.md), 위험과 제한은 [보안 가이드](PLUGIN-SECURITY.md)를 따릅니다. ZIP checksum은 함께 제공되는 `.sha256` 파일로 확인합니다.

build 25의 자동 검사·패키지·실제 화면 확인 상태는 [갤러리 검색 검증 기록](GALLERY-SEARCH-2026-10-05.md)을 확인하세요. build 24의 결과는 [읽기 색상 검증 기록](READING-COLORS-2026-10-05.md)을 확인하세요. build 23의 [열린 PDF 갤러리 검증 기록](OPEN-PDF-GALLERY-2026-10-05.md)과 앞선 디자인·페이지 번역 결과는 당시 결과로 보존하며 이번 검증과 구분합니다.

EmberPDF 이름 변경 전 누적 소스의 검증과 범위는 [10월 1일 소스 갱신 기록](SOURCE-UPDATE-2026-10-01.md)에 있습니다. 9월 22일 패키지의 결과·체크섬은 [0.9.0 배포 검증 기록](RELEASE-VALIDATION-0.9.0.md), 이름 통일 직후 검사는 [9월 23일 소스 갱신 기록](SOURCE-UPDATE-2026-09-23.md)을 따릅니다. 이전 검사 수와 체크섬을 새 빌드 결과로 사용하지 않습니다. 디자인 미리보기는 검증용 문서를 넣은 SwiftUI 화면 자료이며 실제 PDFKit 렌더링 검증과 구분합니다.

- **Office 변환:** 페이지 이미지 방식이며 원문의 문단·표·도형을 개별 객체로 편집하는 변환은 아닙니다. 실제 Office 앱과 버전별 시각 호환성의 수동 검증은 아직 완료되지 않았습니다.
- **HTML·이미지 입력:** HTML은 로컬 WebKit에서 처리하며 복잡한 레이아웃의 결과는 확인이 필요합니다. 로컬 스크립트가 실행될 수 있으므로 신뢰할 수 있는 HTML을 사용하세요. 애니메이션·다중 프레임 이미지는 전체 프레임을 페이지로 펼치지 않습니다.
- **복구·편집:** 자동 복구는 정상 저장을 대체하지 않으며 암호화 문서, 입력 중인 내용, 마지막 대기 시간 이후의 편집까지 보장하지 않습니다. 본문 텍스트 편집은 PDF 객체를 수정·삭제하지만 문서 전체의 숨은 데이터까지 정리하는 보안 가림 기능은 아닙니다. 기존 시각적 교체 주석 아래 원문은 자동으로 제거하지 않습니다.
- **OCR·필기:** OCR 결과로 바꾸는 페이지는 주석 외관을 평탄화하므로 링크·양식·기존 전자서명 상호작용이 유지되지 않을 수 있습니다. 선택하지 않았거나 새 인식 결과가 없는 페이지는 보존합니다. 실제 iPad·Sidecar·Wacom 입력, macOS별 GUI와 File Provider, 장시간 실문서 사용은 자동 검사만으로 검증 완료를 주장하지 않습니다.
- **PDF 아이콘:** 시스템 등록과 실제 파일 아이콘 조회에서는 새 디자인을 확인했습니다. Finder 정보 창에 남은 이전 아이콘 캐시의 갱신은 아직 확인하지 못했습니다.
- **외부 서비스·플러그인:** AI는 사용자가 API 키와 전송 내용을 확인한 요청에만 외부 서비스를 사용합니다. YouTube 학습 예제는 소스 전용이며 이번 앱 번들에서 제외합니다. Schema 5 JavaScript는 별도 실행기와 승인된 JSON API를 사용합니다. Node·임의 파일/네트워크·DOM API를 제공하지 않으며, 3초 dispatch watchdog이 엄격한 메모리 상한이나 모든 코드의 무해성을 보장하는 것은 아닙니다.

중요한 원본은 보관하고, 편집·변환한 결과는 저장 후 확인해 주세요. 기능별 세부 범위는 [프로젝트 README](../README.md)와 [문서 지도](README.md)에서 볼 수 있습니다.

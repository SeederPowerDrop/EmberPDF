# 연속 두 페이지 간격 자동 맞춤

0.9.0 build 49 · 2026-10-10

## 원인과 동작

일부 문서는 보통 페이지 사이에 두 배 너비의 펼침 페이지를 포함한다. PDFKit의 `twoUpContinuous`는 문서에서 가장 넓은 페이지를 기준으로 열을 배치하여, 좁은 두 페이지 사이에도 큰 공백을 만든다. 페이지 간격을 0으로 설정하는 것만으로는 해결되지 않는다. 파일 손상이나 사용자의 조작 오류가 아니다.

‘화면 배치 → 두 페이지 간격 자동 맞춤’을 기본으로 켠다. 상하 연속 두 페이지 모드에서 실제 두 페이지 크기로 각 펼침을 맞추고, 바깥 스크롤 영역이 연속 이동을 담당한다. ‘좌우 넘김’과 함께 보기는 기존 경로를 사용한다. 옵션을 끄면 PDFKit의 기존 연속 배치로 돌아간다.

- 원본 PDFDocument와 PDFPage를 그대로 공유하며 crop/media box를 변경하거나 파일을 재작성하지 않는다.
- 각 펼침은 네이티브 PDFKit 두 페이지 보기다. 글자 선택, 검색 결과, 주석 좌표는 원본 페이지를 사용한다.
- 현재 화면과 양옆 한 펼침만 만든다. 입력·필기 중인 펼침은 편집을 안전하게 마칠 때까지 유지한다.
- 검색·메모 위치는 바깥 화면 중앙으로 이동한다. 다른 펼침이 편집 초안이나 선택을 가져가지 않도록 범위를 확인한다.
- 저장된 스크롤 좌표에는 배치 방식 구분을 함께 남겨 서로 다른 배치의 좌표를 복원하지 않는다.

## 확인 범위

사용자가 허용한 DC Comics PDF(356쪽)를 읽기 전용으로 검사했다. 일반 페이지 너비는 491.52pt이고, 물리 40·356쪽은 983.04pt이다. 기존 1200pt 폭 연속 보기에서 일반 펼침의 가운데 간격은 약 302pt였다.

새 배치는 760·1200·1600pt 폭에서 일반 펼침, 두 배 폭 페이지가 포함된 펼침, 마지막 펼침을 확인했다. 12개 조합 모두 화면 너비에 맞게 붙었고, 가운데 좌표 차이는 PDFKit 반올림 범위인 절댓값 2.31pt 이하였다. 원본 페이지 좌표 왕복, hit testing, 오른쪽 페이지 유지, 원본 bounds·파일 크기·수정 시각 불변을 확인했다. 화면에 유지된 펼침은 이 시험에서 2~5개였다.

새 배치·상호작용·실제 PDF·세션 검사 42개와 기존 방향키·함께 보기·검색·메모·인라인 편집 회귀 검사 120개가 통과했다(합계 162개, 실패 0). 소스 정적 검증과 10개 언어 키 일치 검사도 통과했다.

검사 로그와 화면은 `work/two-page-spacing-build49/`에 보관한다. 자동 검사는 배치·가상화, 회전된 페이지 선택 좌표, 검색·메모 소유권, 인라인 편집 및 실행 취소, 세션 좌표계 복원을 포함한다. 이 기록은 전체 앱의 모든 기능이나 모든 PDF에서의 성능 보증이 아니다.

## 알려진 범위

한 펼침 안에서 두 페이지에 걸친 글자 선택은 PDFKit이 처리한다. 서로 다른 펼침 행을 가로지르는 하나의 드래그 선택은 아직 연결하지 않았다. 필요한 경우 자동 맞춤을 끄고 기존 연속 보기를 사용할 수 있다. 검색 결과 이동과 펼침별 선택·메모 편집은 자동 맞춤에서도 지원한다.

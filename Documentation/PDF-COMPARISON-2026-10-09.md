# PDF 비교 배치·이동 — build 37

EmberPDF 0.9.0 build 37의 로컬 변경이며 공개 GitHub Release를 만들지는 않습니다.

## 진입과 배치

기존 비교 버튼이 `isComparing` 조건 아래에 있어 비교 전에는 탭 개요 메뉴를 통해서만 시작할 수 있었습니다. 탭 막대의 **비교** 버튼을 항상 표시하고, 화면 배치 메뉴에도 **열린 PDF 비교**를 추가했습니다. 문서가 2개 미만이면 비활성화합니다.

열린 PDF 중 2~4개를 선택합니다. 기본 좌우·위아래·격자 배치 이후 PDF 제목을 다른 영역의 왼쪽·오른쪽·위·아래에 놓으면 해당 방향으로 나눕니다. 가운데에 놓으면 위치를 교환합니다. 각 영역의 배치 메뉴에서도 같은 작업을 할 수 있습니다. 분할선을 끌어 크기를 바꾸며 분할선의 메뉴에서 해당 분할의 방향을 바꿉니다. 전체 크기 균등화는 분할 구조를 유지하면서 문서 수에 따라 공간을 배분합니다.

중첩 분할 모델과 실제 사각형 계산을 분리했습니다. PDFView는 문서 ID에 따라 유지되고 위치와 크기만 갱신되므로 배치 부모가 바뀔 때마다 뷰를 다시 만들지 않습니다. 좁은 창에서는 사용 가능한 공간에 맞춰 축소하며 각 영역 밖으로 그리지 않습니다. 기존 단일 방향 배치와 크기 비율을 읽고, 새 혼합 배치·비율·선택 문서·고정을 작업 복원에 저장합니다.

비교 초기에는 영역의 높이와 너비에 맞춰 페이지 전체를 표시하고, 수동 확대 후에는 선택한 배율을 유지합니다. 배치 변경 중 PDFKit이 임시로 보고하는 페이지 번호를 현재 읽는 쪽에 반영하지 않습니다.

## 함께 이동과 고정

이전의 전체 문서 진행률 맞추기 대신 현재 페이지 크기를 기준으로 상대 스크롤 이동량을 전달합니다. 서로 다른 쪽을 맞춰 둔 상태에서 첫 스크롤을 했다고 읽는 위치를 같은 비율로 강제로 바꾸지 않습니다. 가로·세로 이동을 모두 처리하고 창 크기·배치·문서 복원에 따른 움직임은 동기화 입력에서 제외합니다. PDFKit의 스크롤 중 발생하는 미세한 소수점 크기 변화는 실제 레이아웃 변경과 구별합니다.

각 PDF의 이전/다음 버튼과 페이지 번호 입력은 이동 동기화를 켰을 때 같은 페이지 차이를 다른 문서에 적용합니다. 문서별 첫/마지막 페이지에서 독립적으로 멈춥니다. 전체 이전/다음 버튼은 자동 동기화 설정과 별도로 고정되지 않은 PDF들을 넘깁니다.

핀을 켠 PDF는 동기화에서 제외하며 트랙패드·스크롤바·키보드·페이지 버튼·확대 입력으로도 위치를 바꾸지 않습니다. 고정을 해제한 뒤 이동합니다. 텍스트 선택·복사는 유지합니다. 비교는 기존처럼 읽기 전용이며 원본 PDF에 비교 배치를 저장하거나 편집 도구를 실행하지 않습니다.

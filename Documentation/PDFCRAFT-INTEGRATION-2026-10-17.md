# PDF 보존·외부 검증·본문 변경점 비교 — 2026-10-17

EmberPDF 0.9.0 (build 77). pdfcraft의 기능 구성과 검증 방식을 검토한 뒤 EmberPDF의 PDFKit·PDFium·CoreText 구조에 맞춰 구현했다. 검토한 참고 소스는 [pdfcraft의 고정 커밋](https://github.com/storytold/pdfcraft/tree/9e5b70d1c231d7db558e278a2622b519ca063494)이며 해당 프로젝트의 코드를 복사하지 않았다.

## 구현

1. **외부 검증**: `scripts/verify_pdf_outputs.py`가 qpdf 구문 검사, Poppler 텍스트 추출·순서 검사와 표본 페이지 렌더링, pypdf의 정식 `/AcroForm/Fields` 값 검사를 수행한다. 도구가 없거나 실패하면 통과로 처리하지 않는다. 사용자 원본의 기존 qpdf 경고는 진단 결과로 구분하고 앱이 생성한 출력에는 엄격한 종료 코드 0을 요구한다. 원본 SHA-256도 전후 확인한다. 앱 실행 중 외부 도구를 호출하지 않으며 CI가 같은 검사를 실행한다.
2. **본문 원형**: 안전하게 해석할 수 있는 내장 SFNT 글꼴은 제한된 메모리 캐시에 등록한다. 글꼴 설치나 사용자 시스템 변경은 없다. 줄 수·텍스트·기준선과 기존 서식이 일치하면 변경 구간 바깥의 원래 `Tj`/`TJ`·텍스트 행렬을 유지한다. 떨어진 두 줄을 수정할 때 가운데 줄은 연속된 새 텍스트에 포함해 검색·복사 순서를 지킨다. 저장 전 문단 재선택을 검사한다. 원래 글꼴로 표현할 수 없는 글자는 기존 대체 글꼴 경로를 사용한다.
3. **병합·추출**: 분리한 페이지의 목차·해결 가능한 내부 링크·문서 Info·독립된 양식 이름/값을 연결한다. 추출 범위 밖 링크와 목차 대상은 제거하고 남은 하위 항목이 있는 제목은 유지한다. 병합은 기존 실행 취소 이력에 하나의 트랜잭션으로 들어간다. 정식 양식 목록 없이 페이지 Widget만 저장하는 PDFKit 출력에는 기존 객체/스트림을 유지한 증분 목록을 추가한다. 복구·OCR 내보내기·압축 경계에도 확인된 양식 상태를 전달한다.
4. **본문 변경점**: 함께 보기 → **본문 변경점**에서 원본/수정본 두 문서를 선택하고 비교를 실행한다. 텍스트 추가·삭제·수정 및 페이지 추가·삭제를 찾고 항목을 누르면 두 문서의 해당 위치로 이동한다. 고정한 문서는 이동하지 않는다. 비교 중 취소와 원본 변경 감지, 문서별 2,000페이지·페이지별 20만 UTF-16·총 800만 UTF-16·결과 1,000개·처리 시간 상한을 둔다. 변경점 목록의 갱신이 PDFView 전체를 다시 만들지 않도록 수명을 분리했다.

## PDF 안의 기존 글자 편집 벤치마킹

pdfcraft에는 실제 기존 본문을 바꾸는 [replace_line](https://github.com/storytold/pdfcraft/blob/9e5b70d1c231d7db558e278a2622b519ca063494/crates/edit/src/text.rs#L1690-L1707)이 있다. [수정하지 않은 줄 유지](https://github.com/storytold/pdfcraft/blob/9e5b70d1c231d7db558e278a2622b519ca063494/crates/edit/src/text_regions.rs#L612-L634)와 [기준선 처리](https://github.com/storytold/pdfcraft/blob/9e5b70d1c231d7db558e278a2622b519ca063494/crates/edit/src/text_regions.rs#L683-L706)를 참고했다. EmberPDF의 기존 본문 편집기에 내장 글꼴 재사용, 수정 밖 줄 보존, 저장 후 같은 세션의 재편집 검사와 독립 검증을 보강했다. UI를 복제하지 않았다.

사용법은 **편집 → 본문 드래그 선택 → 본문 편집(가T) → 입력**이다. Return은 줄 바꿈, ⌘Return은 적용, Esc는 취소다. 선택 범위의 부분별 서식 도구, 문서 글꼴 목록·수동 글꼴 로딩, 앱을 완전히 종료한 뒤 시스템에 없는 글꼴을 다시 편집하는 완전한 지원은 남은 과제다. 현재 재사용 글꼴 등록은 프로세스 범위이며 앱 재시작 이후의 재편집까지 통과했다고 주장하지 않는다.

## 지원 경계

- 줄 배치나 서식을 바꾸는 수정은 해당 문단을 다시 조판한다. 글꼴 프로그램이 불완전하거나 사용 권한이 제한되거나 동일 이름과 다른 프로그램이 충돌하면 기존 안전한 대체 경로를 쓴다. 대체 글꼴도 표현할 수 없는 문자는 적용 전에 거절한다. 모든 PDF 글꼴을 그대로 재사용한다는 뜻은 아니다.
- 팔레트(Indexed) 이미지가 있는 페이지는 원래 이미지 자원과 보간 설정을 보존한다. 자원 사전만 제한적으로 검사하며 일반 RGB/JPEG 페이지는 기존 복사 경로를 쓴다. 이 경로에는 페이지당 64MiB·조립당 512MiB의 원본 그래프 상한이 있다.
- 사용자 지정 페이지 번호, 첨부·레이어·접근성 태그·XFA·전자서명과 복잡한 공유 양식은 PDFKit 페이지 조립으로 보존을 보장할 수 없어 조립 전에 거절한다. 단순 양식 보완은 암호화되지 않은 독립 terminal Widget 범위이며, 암호화 출력은 기존 보호 저장 경로를 유지한다.
- 비교는 추출 가능한 텍스트와 페이지 구성에 한정한다. 이미지·배치·주석·잉크 차이는 검출하지 않는다. 추출 텍스트가 없는 페이지와 처리 상한 초과는 별도로 표시하며 일치 판정을 내리지 않는다. OCR이 없는 스캔 문서는 먼저 OCR이 필요하다.
- 언어 변경은 문서의 비교용 revision을 바꾸지 않는다. 문서를 편집하면 이전 결과를 무효화하고 재비교를 안내한다.

## 발견해 수정한 문제

- PDFKit이 병합 도중 Widget 이름·값을 바꾸거나 정식 필드 목록에서 누락하는 경우를 보완했다. 충돌하는 공유 필드는 변경 전에 거절한다.
- PDFKit 직렬화의 classic xref에서 존재하지 않는 offset 0 객체를 사용 중(`n`)으로 쓰는 항목을 발견했다. 전체 표·trailer·객체 경계를 확인한 경우에만 해당 한 바이트를 free(`f`)로 고치며 객체·스트림·오프셋·파일 길이는 바꾸지 않는다. 후보가 없는 일반 PDF는 파일 끝 4KiB와 최대 8MiB의 xref 확인으로 끝내며, 후보가 있을 때만 객체 헤더와 보호 구조를 추가 검사한다.
- 오래된 OCR 스캔 추출 시 PDFKit이 원래 없던 `/Interpolate`를 `true`로 바꿔 렌더링이 달라지는 문제를 수정했다. 해당 Indexed 이미지 페이지만 원래 자원 그래프를 유지하고 주석·내부 링크는 별도로 연결한다.
- 개발 도구에 포함된 Poppler의 잘못된 CMap 경로가 종료 코드 0으로 한국어 추출을 누락하는 문제를 검사 중 발견했다. 정상 CMap이 있는 도구로 재검사하고, 드라이버는 도구의 구문 오류 출력을 성공으로 처리하지 않게 했다. 이는 앱의 한국어 글꼴 설치 변경을 요구하지 않는다.

## 검증 기록

서로 다른 실행의 중복 테스트 수는 합산하지 않았다. 전체 분리 회귀와 마지막 Release 통합 검사를 구분한다.

- 이전 시험 폴더의 382개 중 기존 대용량 표본 28개와 한국어 교재 2개, 총 30개·11,208페이지·5,375,774,121바이트를 선정했다. 원본 qpdf 진단에서 21개는 엄격 검사 통과, 9개는 기존 경고였다. 올바른 한국어 CMap을 갖춘 Poppler의 추가 진단은 28개 통과, 2개에서 기존 xref/선택적 콘텐츠 구조 오류를 검출했다. 종료 코드 0이어도 Poppler의 Syntax Error는 실패로 처리한다. 이는 앱이 생성한 출력의 보존 검증과 구분한다. 원본 30개의 SHA-256·크기·수정 시각은 시험 전후 모두 동일했다.
- 전체 분리 회귀 205개 클래스·1,847개 고유 테스트를 실행했다. 정상 호스트의 플러그인 173개 재시험을 반영하면 **1,831개 통과·16개 건너뜀·실패 0개**다. 건너뜀은 새 통합 opt-in 3개, 기존 opt-in 11개, macOS 15 PDFKit 조건 2개이며 실제 PDF opt-in은 아래처럼 별도 실행했다. 처음 분리 빌드의 helper 위치와 제한된 샌드박스의 클립보드 접근 때문에 난 환경 실패는 정상 helper/호스트 경로로 전체 플러그인 배치를 재실행해 확인했다. 원시 실패 로그도 남겼다.
- 최종 소스의 **Release 통합 108개 통과·건너뜀 0·실패 0**: 본문 원형 11개(실제 한국어 교재 2권의 4회 수정·저장·재편집 포함), 양식 14개, 구조 보존 15개(마지막 팔레트 회귀 2개 포함), 실제 30문서 추출 1개, xref 5개, 독립 검사 출력 fixture 1개, 비교 16개, 언어 3개, 편집 이력 24개, 복구 8개, 압축 10개다. 배포와 같은 `.lproj`가 있는 별도 QA 앱 리소스 호스트에서 실행했다. 초기 bare SwiftPM Release 호스트에는 앱 리소스가 없어 언어 조회가 실패했고 비교 보고서 환경변수도 누락돼 재설정했다. 제품 코드를 테스트용으로 바꾸지 않았다.
- 독립 검사는 생성한 **27개 출력 PDF(기본 저장·추출·병합·편집 4개 + 본문 16개 + 실제 표본 추출 7개)** 모두 qpdf 엄격 종료 0·텍스트·표본 렌더링을 통과했다. 기본 fixture의 정식 양식 값과 변경하지 않은 페이지 렌더도 통과했다. 드라이버 자체 회귀 10개도 통과했다.
- 실제 문서 30개 중 7개는 첫·중간·끝 21쪽의 추출을 지원했고, 6개는 사용자 지정 페이지 번호, 17개는 특수 구조를 안전하게 보존할 수 없어 변경 전에 거절했다. **30개 전체의 병합·추출을 지원한다는 의미가 아니다.** 지원 출력은 독립 qpdf 추출 참조와 단어 순서 100%·내장 이미지 픽셀 일치를 확인했다. 21쪽 중 13쪽은 렌더가 완전히 일치했고 나머지의 최대 다른 픽셀 비율은 약 0.117%, 평균 채널 오차는 255 기준 0.226 미만이었다. 일반 표본에는 0.2%/0.3 상한을 적용했고, 보간 버그를 수정한 OCR 문서의 3쪽은 모두 0 차이를 요구했다. 마지막 결과에서는 PDFKit 추출 텍스트의 휴리스틱 차이도 없었다.
- 팔레트 검사 중 pypdf 6.10.0의 필터 없는 Indexed 이미지 디코더가 팔레트를 누락하는 오류도 발견했다. 읽기 전용 입력의 샘플·팔레트·ICC 데이터가 동일함을 확인하고 분리된 Flate 사본을 공개 `decode_as_image()` API로 읽도록 드라이버를 보완했다. 데이터나 색상 변경은 계속 실패하며 Poppler의 0 픽셀 차이 요구도 유지한다. 파일별로 reader/image 순환 참조를 회수해 검사 도중 메모리와 임시 공간 사용을 줄였다.
- 새 비교 검사 16개(실제 30개 표본 포함), 실제 언어 전환/지역화 검사 3개 통과. 한국어·영어·일본어·중국어 간체·베트남어·스페인어·프랑스어·독일어·러시아어·아랍어에 새 문자열을 추가했다. 10개 언어의 실제 사이드바 렌더링을 만들고 한국어·독일어·아랍어를 시각 확인했다.
- 기존 실제 30문서 시험은 표본 90페이지 렌더링과 30문서 복원을 완료했다. 별도 PDFKit UI 시험은 약 1.39GB의 3문서, 화면 객체 생성 62회·표본 래스터화 52회를 80.78초에 완료했고 최종 잔존 view/state/document는 모두 0이었다. 전체 앱의 실제 입력 지연이나 다른 앱과의 성능 비교는 아니다.
- 최초 PDFKit UI 시험은 `PDFTileSurface.releaseSurface` 내부의 `CFRelease(NULL)`로 중단됐다. 동일 시험의 분리 재시도는 통과했다. 당시 초기 일반 탭 교체 경로로 새 변경점 서비스는 실행되지 않았다. 이 결과만으로 macOS PDFKit의 원인이나 모든 환경에서의 무결함을 확정하지 않는다. 최초 로그와 재시도 결과를 모두 보존한다.

로컬 상세 자료는 `work/pdfcraft-integration/`에 있으며 비공개 PDF·추출 본문·개인 경로는 배포 문서나 저장소에 포함하지 않는다. 원본의 전체 내용을 비교한 수치와 표본 페이지 검사 수치를 혼동하지 않는다.

## 재현

일반 회귀는 `scripts/validate_project.sh`와 `scripts/run_test_batches.sh`를 실행한다. 독립 PDF 검사에는 qpdf·Poppler와 pypdf 6.10.0·Pillow 12.3.0이 필요하다.

```sh
python3 -m unittest discover -s Tests/ExternalValidation
EMBER_EXTERNAL_FIXTURE_DIRECTORY="$PWD/work/pdf-oracle-fixtures" \
  swift test --disable-sandbox --filter PDFExternalValidationFixtureTests
python3 scripts/verify_pdf_outputs.py \
  --manifest work/pdf-oracle-fixtures/manifest.json \
  --output-directory work/pdf-oracle-results
```

실제 PDF 검사는 명시한 개인 manifest/폴더가 있을 때만 실행하는 opt-in 테스트다. `EMBER_BODY_SOURCE_PDF_DIRECTORY`, `EMBER_PAGE_STRUCTURE_CORPUS_MANIFEST`, `EMBER_PAGE_STRUCTURE_QA_DIRECTORY`, `EMBER_DIFFERENCE_CORPUS_MANIFEST`와 절대 경로 `EMBER_DIFFERENCE_CORPUS_REPORT`, `EMBER_PERF_MANIFEST`, `EMBER_STRESS_MANIFEST`를 해당 검사에 전달한다. 원본을 직접 저장하지 않고 분리된 메모리/출력 디렉터리를 사용한다.

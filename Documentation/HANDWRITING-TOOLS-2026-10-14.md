# 필기 도구·조작감과 이미지 좌표 수정 — 2026-10-14

대상: **EmberPDF 0.9.0 (build 70) Developer Preview**

## 사용 흐름

사용자가 요청한 Flexcil의 필기 도구와 조작감을 참고했습니다. 공식 [펜 도구 설명](https://support.flexcil.com/hc/en-us/articles/8164459936537-Pen-toolbar)의 빠른 펜 선택, 다시 눌러 설정, 즐겨찾기와 도형 흐름을 마우스·키보드로 쓰는 macOS 화면에 맞춥니다.

- 편집·학습 모드의 기존 두 번째 도구줄에 공통 필기 도구를 배치합니다. 저장한 펜 4개는 바로 보이고, 별표 메뉴에서 최대 8개를 적용·수정·교체·삭제합니다. 색상·굵기·불투명도·압력 설정·종류·도형·선 패턴을 로컬 환경설정에 보관합니다.
- 펜을 한 번 누르면 선택하고, 이미 선택한 펜을 다시 누르면 설정을 엽니다. 선택된 즐겨찾기의 설정을 바꾸면 해당 즐겨찾기도 갱신됩니다. 현재 펜 설정 버튼은 즐겨찾기를 바꾸지 않습니다.
- 자유 필기·직선·사각형·타원, 실선·점선, 각진·둥근 형광펜을 제공합니다. 도형 메뉴를 고르면 펜으로 전환합니다. 마우스는 일정 굵기, 지원 태블릿의 자유 필기는 압력을 사용하며 도형은 압력을 적용하지 않습니다.
- 미리보기와 저장 시 같은 벡터 도형을 사용합니다. 부분 지우기·이동·확대 후에도 점선의 위상이 이어지고, 지운 도형의 빈 부분을 다시 닫지 않습니다. 이전 필기 메타데이터도 기본 옵션으로 읽습니다.
- 읽기용 PDF의 선택 기능은 필기 권한과 독립적으로 유지합니다. 도구 설정 변경은 PDF의 편집 기록을 만들지 않습니다.

## 입력 처리

자유 필기는 새 선분의 굵기를 두 샘플로 계산하고, 바뀐 영역과 그곳을 지나는 기존 선분을 다시 그립니다. 매 화면 갱신에서 PDFKit 좌표 변환은 샘플마다 반복하지 않고 세 점으로 구한 공통 변환을 사용합니다. 긴 획은 입력 수와 점선 확장 수에 상한을 둡니다. 획 시작 시 설정을 고정하여 그리는 중 설정 변경 때문에 확정 모양이 달라지지 않게 합니다. 마지막 mouseUp 좌표도 보존하고 Esc로 현재 획을 취소합니다.

## 이미지 잘림 수정

사용자 스크린샷처럼 선택 상자 안에서 이미지가 다른 위치에 그려지는 문제를 재현했습니다. 이미지 주석의 draw 문맥에 `PDFPage.transform(for:)`가 빠져 페이지 원점·CropBox·회전에 따라 그림이 이동하고 잘렸습니다. 이미지 주석과 압축된 이미지 주석에 변환을 적용하고, 압축 서비스의 직접 appearance 추출은 그 변환을 상쇄합니다. 압축된 이미지의 원래 appearance를 현재 주석 크기에 맞추어 이동·확대도 반영합니다.

원본 JPEG 보존과 명시적으로 자른 영역의 픽셀 제거 경로는 유지합니다. 기존 파일에 이미 잘린 appearance로 저장된 이미지를 자동 복원하지는 않습니다. 이 경우 원본 이미지를 다시 삽입해야 합니다.

## 검증

관련 XCTest **186개 통과, 실패 0**. 로그: `work/ink70/regression-tests.log`. 이전 빌드의 검사 수와 합산하지 않습니다. 프로젝트 정적 검사와 10개 언어 키 일치 검사를 통과했습니다(`work/ink70/static-validation.log`).

- 이미지: 독립적인 PDF 벡터 색상 표식을 기준으로 원점이 다른 MediaBox/CropBox, 0/90/180/270도 회전, 전체 이미지·명시적 crop·이동·크기 변경·압축·저장·재열기를 비교합니다. 수정 전에는 새 이미지 테스트 4개에서 assertion 156개가 실패했고 수정 후 모두 통과했습니다. 원본 JPEG·사진 삽입 승인·이미지 편집·용량·압축 서비스와 workspace 검사도 포함합니다.
- 필기: 모든 종류의 미리보기/확정 좌표·색상, 자유 필기·도형·점선·끝 모양, 부분 지우기·복사·저장·재열기·실행 취소, 설정 고정·최종 좌표·Esc·합성 태블릿 압력 이벤트를 검사합니다. PDFKit 저장 사각형의 반올림은 최대 0.0001pt까지 허용하되 획과 점의 개수 및 점선 유무는 정확하게 비교합니다.
- 입력 비용: 8,000개 입력 점의 굵기 계산이 15,999개 샘플 처리에 그치고, 마지막 변경 영역은 10pt 미만이며 렌더러에 전달되는 주변 점도 10개 미만임을 검사합니다. 실제 화면 FPS나 경쟁 앱과의 측정 비교는 아닙니다.
- 즐겨찾기: 저장/재시작 복원·최대 수·빈 목록·유효하지 않은 값 거부·권한/모드 경계·PDF 변경 없음 검사를 포함합니다.
- 화면: 한국어/영어 × 밝은/어두운 테마에서 1180/1440pt 도구줄과 설정 화면 총 32개를 네이티브 NSWindow로 렌더링했습니다. 두 줄 도구 구조, 설정의 실제 AppKit 획 미리보기, 도형·형광펜·슬라이더와 아이콘을 확인했습니다. 마지막 현지화 보완 후 UI 검사 1개를 다시 통과했습니다(`work/ink70/ui-final-tests.log`; 중복 합산하지 않음). 증거는 `work/ink70/ui/`, 이미지 좌표 PNG/PDF는 `work/ink70/image-after/`에 있습니다.

실제 태블릿·Sidecar 하드웨어 및 사용자 원본 PDF에서의 수동 검증은 하지 않았습니다. Flexcil과의 FPS 비교 수치를 주장하지 않습니다.

## 후속 설치와 실제 PDFView 확인

이미지가 계속 잘린다는 후속 신고를 확인했을 때 `/Applications/EmberPDF.app`은 build 58이었습니다. 사용자의 설치 승인 후 남아 있던 구버전 창의 미저장 편집을 `work/image71/EmberPDF-pre-update-edits.pdf`로 별도 보관하고 정상 종료했습니다. 기존 앱을 `work/image71/EmberPDF-build58-replaced.app`에 백업한 뒤 기본 설치 앱을 build 70으로 교체했습니다. 설치 보고서는 `work/image71/install-report.json`입니다. 설치본과 패키지 원본의 실행 파일 SHA-256 일치 및 기본 설치 경로에서의 새 앱 실행을 확인했습니다.

생산 `ImageStampAnnotation` 소스를 직접 컴파일한 독립 네이티브 앱(`work/image71/ImagePlacementQA.app`)에서 실제 PDFView 화면을 CUA로 관찰했습니다. CropBox 원점이 (20, 30)인 페이지에서 일반 PDF 본문의 네 색상 기준 그림과 원본 래스터·원본 JPEG 삽입 결과를 나란히 비교했습니다. 최초 표시, 이동·크기 변경, 90도 회전, 메모리 저장·다시 열기 후 모두 네 모서리 전체와 위치가 일치했습니다. 검증 창은 종료했고 사용자 원본 PDF에는 검증용 이미지를 추가하지 않았습니다.

PDFView의 `cacheDisplay`/레이어 캡처를 사용한 실험은 주석 레이어를 누락하므로 자동 통과 근거로 쓰지 않았습니다. 실험 파일은 기본 테스트 대상 밖인 `work/image71/`에 보관했습니다. 이번 후속 작업에서 생산 코드를 추가 변경하거나 build 71을 배포하지 않았습니다.

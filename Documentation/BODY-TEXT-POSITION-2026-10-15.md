# 본문 편집 위치·선택·반복 편집 — 2026-10-15

대상: **EmberPDF 0.9.0 (build 72) Developer Preview**.

## 변경

- 글꼴이나 크기를 바꿔도 원래 PDF 글자의 기준선을 유지한다. 교재의 9.9626pt처럼 소수점 크기를 입력 필드에서 10pt로 바꿀 때 생기던 아래쪽 이동도 방지한다.
- 페이지 위 편집기는 실제 TextKit 기준선을 원문 기준선에 맞춘다. 저장 엔진과 같은 줄바꿈 너비·줄 간격·대체 글꼴을 사용하며, 화면 폭이 좁아졌다는 이유로 문단을 다시 줄바꿈하지 않는다. 긴 초안 내부 스크롤은 편집 상자 위치에 영향을 주지 않는다.
- 적용·실행 취소·다시 실행으로 PDFPage가 교체되어도 확대율과 스크롤 위치를 보존한다. 너비 맞춤의 지연된 페이지 이동과 두 페이지 보기의 오른쪽 페이지도 처리한다. 이후 사용자의 이동·확대가 우선한다.
- PDF가 단어 사이 공백을 위치 정보로 표현한 경우에도 실제 글자 소유권과 원문의 공백을 대조해 드래그한 범위를 편집기로 넘긴다. 공백을 제외한 글자가 일치하지 않으면 편집 대상을 추측하지 않는다.
- 같은 Form에 묶인 호환되는 연속 본문은 호환되는 전체 문단을 하나의 초안으로 다루되, 실제 입력 선택 범위는 사용자가 선택한 부분 그대로 유지한다. 이전 버전에서 수정·저장한 여러 줄도 같은 경로를 사용한다.
- 글꼴 리소스를 Form 안에서 격리한다. 문단 전체를 교체할 때 기존 대상 Form도 함께 교체해, 남아 있는 잘못된 글꼴 참조가 후속 편집을 막지 않게 한다. 다른 문장·그림의 리소스를 합치지 않는다.
- 일반적인 본문 줄은 검증한 원본 텍스트 명령만 교체하고 나머지 그래픽 명령·리소스를 그대로 보존한다. 페이지에 CMYK·별색·그라데이션·특수 선 설정이 있다는 이유로 정상 본문까지 막지 않는다. 토큰과 실제 PDF 글자의 그리기 순서를 각각 확인하며, 기존 글자를 숨기거나 가리는 방식이 아니다.
- PDFium이 서로 다른 임베디드 글꼴을 같은 이름으로 합치지 않도록 편집 중에만 별칭을 사용하고 반환 전에 원래 이름을 복원한다. 원본 스트림을 보존하는 편집 경로는 이 재생성 자체를 거치지 않는다. 반복 수정 시 사용하지 않는 이전 편집용 Form 리소스도 제거한다.

## 범위

네이티브 PDF 본문 편집이며 가림 주석을 추가하는 방식이 아니다. 대상 밖 원문과 도형의 내용·그리기 순서 및 문서 편집 권한 검사를 유지한다. 서로 다른 서식이 섞인 선택, 공유 Form, 특수 클리핑·기울임·합성, ActualText로 묶인 문구 및 한 블록의 여러 출력 명령처럼 정확히 분리할 수 없는 구조는 여전히 거부할 수 있다. 모든 PDF를 Word처럼 재배치하는 기능은 아니다.

## 검증

- 관련 XCTest 153개 통과. 기준선, 줄바꿈·스크롤, 확대·페이지 보기, 부분 선택, 반복 편집, 저장·재열기, 실행 취소, 권한, 크기, 원본 그래픽·글꼴 보존을 포함한다. 전체 저장소 테스트 결과는 아니다. 로그: `work/text72/regression-tests.log`.
- 실제 Physics 교재의 **파일 969번째 페이지(인쇄 940쪽)**에서 첫 줄 편집·저장·재열기·재편집 성공. 편집 직후 대상 밖 모든 픽셀이 원본과 동일하다. 저장 후에는 같은 PDFKit 저장 과정을 거친 원본과 대상 밖 픽셀이 동일하다. 로그: `work/text72/physics/apply/results.log`.
- 이 교재의 **인쇄 969쪽(파일 998번째 페이지)** 본문은 한 블록에 여러 출력 명령이 있어 이번의 원본 보존 경로로 편집하지 않는다. 페이지 번호를 혼동해 지원 범위를 확대해 주장하지 않는다.
- 실제 Ultrafast Optics의 파일 310쪽에서 위치 간격으로 저장된 공백을 포함하는 본문·제목을 선택하고 저장 후 재수정했다. 사용자 원본은 변경하지 않았다.
- Physics 969쪽의 10줄·854자 편집기 진입은 138–156ms, 적용은 199–223ms였다(개발용 독립 실행 3회). 드래그 중 매 프레임 경로가 아닌, 선택 후 편집기 열기·적용 비용이다. 원본 확인용 페이지 생성은 선택 줄 수와 관계없이 2회로 제한한다.
- 실제 교재 사본을 Poppler로 렌더링하여 주변 본문·수식·그림과 수정 결과를 확인했다.

## build 74 — 태그 본문과 확대 선명도

- `/Lang`, `/MCID` 태그 아래에서 한 BT/ET 안에 단어별 Tj/TJ가 나뉜 본문을 전체 블록 단위로 교체한다. 논리적 공백만 담은 ActualText는 빈 잉크 경계를 확인하고 처리한다. 비공백 ActualText, 보이는 글자를 공백으로 감춘 객체, 회전·기울임, 지원하지 않는 표시 범위는 계속 거부한다.
- 원본 명령과 native 객체 순서를 검증하고, 편집 대상 밖 그림·색·폰트 리소스를 보존한다. 빈 객체를 포함한 삭제 범위를 재확인하고 편집 중 원본 스트림이 바뀌면 적용하지 않는다. 겹치는 중복 문자열은 다른 위치로 추측하여 바꾸지 않는다.
- 95%, 98% 같은 PDF 글꼴 가로 비율을 편집창과 출력에 유지한다. 가로 비율 적용과 폰트 해상도를 분리하여 시스템 글꼴의 point size가 중복 적용되지 않게 한다.
- 저장 후 PDFium이 다음 객체와의 경계에 합성하는 끝 공백만 prefix 검증에서 정규화한다. 내부 문자와 잉크 위치 검증은 유지한다.
- 읽기 색상 필터를 확대되는 clip view에서 화면 크기가 일정한 scroll view로 이동했다. 페이지 타일과 편집 오버레이는 기존 계층을 유지하며 PDF 페이지를 비트맵으로 바꾸지 않는다.

실제 영양소 교재의 파일 83페이지에서 ‘수확한’을 ‘수확된’으로 바꾸고 저장·재열기 후 다시 ‘수확한’으로 재편집했다. 원본 파일은 변경하지 않았다. 편집 직후 대상 줄 밖 픽셀은 원본과 동일하다. 2배 macOS 렌더에서 저장된 control 사본과 재편집 사본의 바깥 픽셀 차이도 0이며 611자가 유지된다. 파일 49·81·85쪽에서도 같은 유형의 본문 진입을 확인했다. 제목과 장 번호처럼 서로 다른 서식이 섞인 선택 전체를 허용했다는 뜻은 아니다.

Poppler는 편집하지 않은 PDFKit 저장 control에서도 Adobe-Korea1 CMap 누락/Unknown font 오류로 본문을 누락했다. 이 파일의 저장 후 시각 검증은 macOS CoreGraphics/PDFKit 렌더와 검색·텍스트 비교를 사용했다. 원본과 PDFKit 저장 control 사이에는 상단 삽화에서 508픽셀 차이가 있어, 저장 후 비교는 동일한 저장 과정을 거친 control 기준이다.

별도 AppKit 비교 창의 400% 확대에서 원본·수정 전·수정 후를 나란히 확인했다. 수정 전 색상 필터의 글자·가는 선 흐림이 수정 후에는 원본 수준으로 보인다. 50~800% 확대와 읽기 색상 전환의 viewport·필터·페이지 보존은 회귀 테스트로 검사한다.

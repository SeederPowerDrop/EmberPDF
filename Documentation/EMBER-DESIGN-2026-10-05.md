# Ember 작업 화면 — 2026-10-05

EmberPDF 0.9.0 (build 22)의 화면을 잉걸불의 온기와 차분한 작업 공간이라는
방향으로 정리했다. 읽는 문서, 현재 작업과 다시 열 문서를 쉽게 찾도록 기존
기능과 배치를 유지하면서 색상·선택 표시·도구의 시각적 위계를 조정했다.

## 적용 내용

- 어두운 화면은 따뜻한 숯빛, 밝은 화면은 미색 표면을 사용한다. 본문 UI 글자는
  중립적인 밝고 어두운 색을 유지하고, 활성 상태와 주요 행동에 앰버를 쓴다.
- 활성 탭과 그룹에 얇은 테두리·밑줄·아이콘 색을 함께 사용한다. 탭 제목은
  11pt에서 12pt로 키웠다. 키보드 포커스는 별도의 분명한 앰버 테두리로 표시한다.
- 썸네일 선택은 은은한 배경과 테두리로 구분하며 기존 체크 표시를 유지한다.
  탭·썸네일 hover의 짧은 전환은 macOS의 동작 줄이기 설정을 따른다.
- 도구줄 높이를 42pt에서 46pt로 조정하고 버튼 hover와 활성 페이지 패널 표시를
  정리했다. 기존 집중 보기 동작에는 이름을 붙여 접근하기 쉽게 했다.
- 홈의 이름·열기 버튼·최근 문서와 정보 창의 제목·링크·후원 버튼도 공통 테마를
  사용한다. 정보 창의 강한 그라데이션·입체 테두리·그림자를 줄였다.
- PDFKit 주변 배경은 SwiftUI와 같은 팔레트를 사용하고 네이티브 appearance
  변경을 따른다. PDF의 종이색·본문·그림·주석·저장 데이터는 바꾸지 않는다.
- 기본 모드, 문서·탭·워크스페이스 데이터, 키보드 명령, 플러그인 동작과 기존
  사용자의 테마 선택은 유지한다. build 21의 페이지 번역 플러그인도 포함한다.

## 시각 확인 방식

실제 `PDFTabBar`, `WorkspaceToolbar`, `PageSidebarView`, `WelcomeView`와
`AboutView`를 별도 XCTest 렌더링 도구에서 검토한다. 작업 화면은 1420×900과
1180×690 크기의 어두운·밝은 화면을 사용한다. 사용자 PDF와 세션은 사용하지 않는다.

미리보기의 도구와 패널은 실제 앱 구성요소다. 문서 영역에는 직접 만든 시험 PDF의
페이지 이미지를 넣는다. 이는 macOS 15에서 PDFKit의 오프스크린 타일 정리 문제가
있기 때문이며, 실행 중인 앱의 전체 화면이나 PDFKit 조작 검증으로 표시하지 않는다.
최초 미리보기 작성 시에는 직접 실행 확인이 대기 중이었으며, 아래 후속 실행
기록과 오프스크린 자료를 구분한다.

## 검증 결과

- 기존 메뉴·탭 그룹·페이지 패널·검색 UI·현지화·정보 화면 테스트 80개와 임시 시각
  검사 1개, 총 **81개 통과, 실패 0**. 후속 색상·비활성 상태 보완 뒤 시각 검사
  2회도 통과했다. 임시 테스트 파일은 제거했다.
- 정적 검사와 `git diff --check` 통과. build 22와 10개 언어를 확인했다.
- 실제 UI 구성요소의 다크·라이트 작업 화면과 홈, 10개 언어의 정보 창 이미지를
  생성했다. 문서 비트맵은 최종 검토에서 4배 해상도로 다시 렌더링했다.
- 작업 화면의 두 크기, 한국어·독일어·아랍어 정보 창을 시각 확인했다. 비활성
  도구 버튼은 이미지에 직접 지정한 색상까지 함께 흐려지는 것을 확인했다.
- 네이티브 강조 버튼의 배경은 오프스크린 캡처에서 빠지므로 해당 시스템 컨트롤의
  실제 강조색·전경 조합까지 확인한 것으로 주장하지 않는다.

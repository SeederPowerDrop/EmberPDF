# 갤러리 탐색과 본문 검색 — 2026-10-05

대상 소스는 **EmberPDF 0.9.0 (build 25) Developer Preview**다. 이 문서는 build 24의 [읽기 색상 기록](READING-COLORS-2026-10-05.md), build 23의 [열린 PDF 갤러리 기록](OPEN-PDF-GALLERY-2026-10-05.md) 이후 갤러리 확장을 다룬다. 이전 빌드의 검사 수·시간·체크섬은 새 결과로 재사용하지 않는다. GitHub에 새 Release를 공개하는 작업은 포함하지 않는다.

## 사용 흐름

- 탭 막대의 갤러리 버튼이나 **보기 → 열린 PDF 갤러리 (`⇧⌘G`)**로 연다.
- 갤러리 안에서 워크스페이스를 선택하거나 모든 워크스페이스의 열린 문서를 둘러본다. 탭 선택 메뉴와 탭 그룹으로 범위를 좁혀 필요한 문서를 찾는다.
- 검색창에 문서 이름 또는 본문의 단어·문구를 입력한다. 문서 이름이 맞는 카드와 PDF 본문에서 찾은 결과를 보여 준다.
- 본문 결과는 찾은 문장을 강조한 발췌문과 해당 페이지 미리보기를 제공한다. 문서별로 첫 세 결과를 보여 주며, 더 보기로 나머지를 펼친다. 발췌문 위로 포인터를 옮기면 해당 페이지 미리보기가 바뀐다. 결과를 선택하면 그 워크스페이스의 문서를 열고 해당 페이지·위치로 이동한다.
- 검색 중에도 진행 상황과 먼저 찾은 결과를 보여 준다. 검색어나 탐색 범위를 바꾸거나 갤러리를 닫으면 이전 검색을 취소한다.

## 원본과 탐색 상태

갤러리에서 워크스페이스나 그룹을 둘러보는 것과 실제로 읽을 문서를 여는 동작을 구분한다. 카드를 선택하기 전에는 기존 활성 문서와 페이지를 바꾸지 않는다. 내용 검색과 미리보기는 문서 편집이 아니며 PDF 파일·주석·저장 상태를 수정하지 않는다. 검색 결과의 강조 표시는 화면 표시로만 사용한다.

내용 검색은 PDF의 추출 가능한 텍스트를 이 Mac에서 찾는다. 외부 번역·AI·검색 서비스로 문서를 보내지 않고 별도의 본문 색인 파일을 저장하지 않는다. 잠긴 문서는 비밀번호를 추측하지 않으며, 문서의 복사 권한을 존중한다. 이미지로만 된 페이지는 본문 검색에 잡히지 않을 수 있고 검색을 위해 자동으로 OCR을 수행하지 않는다. 파일을 읽을 수 없거나 텍스트를 검색할 수 없는 문서는 그 상태를 알린다.

큰 PDF를 여러 개 열어 둔 경우에도 한 번에 검색하는 문서는 하나로 제한한다. 검색 결과는 전체 200곳, 문서당 12곳, 페이지당 4곳을 기본 상한으로 두며, 일부만 표시할 때 검색어를 구체화하거나 문서 안에서 검색을 이어 가도록 안내한다. 입력 뒤 220ms를 기다린 후 검색을 시작한다. 휴면 탭은 별도 actor가 소유하는 임시 PDF 한 개로 읽고, 기본 6페이지 묶음마다 진행 결과를 넘긴다. 기존에 열린 문서는 소유 actor에서 읽어 저장하지 않은 편집도 반영한다. 휴면 탭을 전부 활성 문서로 올리지 않는다.

`PDFGalleryDocument`는 워크스페이스와 원래 탭 식별자를 함께 유지한다. `PDFGallerySearchController`는 요청 식별자와 취소를 사용해 이전 검색의 결과가 새로운 검색을 덮지 않도록 한다. 검색 중 revision·문서 식별자·파일 버전이 바뀌면 해당 결과를 무효화한다. `PDFGallerySearchConfiguration`이 결과 수와 게시 간격을 정의하며, 본문 검색은 기존 `PDFSearchEngine`의 정규화·발췌·위치 계산을 사용한다.

페이지 미리보기는 기존 갤러리 서비스를 사용하며 서비스 캐시는 32개·24 MiB로 제한한다. 화면은 찾은 페이지의 미리보기만 요청한다. 검색 범위의 모든 페이지를 이미지로 만들거나 본문 전체를 영구 색인하지 않는다.

읽기 색상은 갤러리 결과 페이지에도 적용된다. 원본 색상의 공유 미리보기 캐시는 유지하며, 저장·내보내기에 읽기 색상이나 검색 강조를 굽지 않는다.

새 검색 테스트는 정규화된 본문·이름 검색, 다른 워크스페이스의 휴면 탭, 저장하지 않은 병합 문서의 본문, 잠금·복사 제한·텍스트 없음·읽기 실패, 결과 상한, 취소 이후 결과 보존, 새 검색에 이전 결과가 끼어들지 않는지, 파일 교체와 revision 변경을 검증한다. 이동 테스트는 목표 문서·페이지·검색 위치로의 이동과 강조, 낡은 범위·내용·워크스페이스/탭 쌍의 거부, 진행 중인 기존 문서 검색의 취소를 검증한다.

검색 미리보기는 지정한 결과 페이지의 선택 표시, 휴면 탭을 깨우지 않는 읽기, 잘못되거나 오래된 위치의 강조 배제, 회전·잘라낸 페이지의 좌표를 검증한다. 원본 미리보기 픽셀과 읽기 상태를 유지하는지 함께 검사한다. 복사 비트가 꺼져 있어도 소유자 권한으로 연 암호화 문서에서는 본문 검색과 미리보기 강조의 권한 판단을 일치시켰다. 반대로 소유자 권한 없이 추출이 제한된 문서는 강조하지 않는다. 실제 암호화 PDF의 소유자·사용자 권한 시나리오를 기존 미리보기 테스트에 포함해 4개 모두 다시 통과했다. 이 재실행을 별개 테스트 수로 더하지 않아 고유 검사 합계는 54개다.

정적 검사에서는 사용자 SwiftPM 캐시에 쓸 수 없다는 경고가 있었으나 구성 검사 결과는 통과했다. 최종 Release 빌드에도 SDK의 디버그 모듈 캐시 경로 경고가 있었으나 컴파일·링크와 패키지 검증은 완료됐다.

### 실제 PDF 스트레스 검사

사용자 Downloads의 PDF 40개를 **두 개의 임시 워크스페이스**로 구성해 모델·서비스 통합 검사를 실행했다. 입력 합계는 **5,654,605,688바이트**, 문서가 보고한 총 페이지 수는 **13,677페이지**다. 사용자 영구 세션이나 최근 문서 목록은 이 검사에서 갱신하지 않았다.

일반적인 영문 단어 `the`를 검색하면서 검사 시간을 제한하기 위해 테스트 전용 상한을 **전체 80곳·문서당 3곳·페이지당 2곳**으로 지정했다. 제품 기본값인 전체 200곳·문서당 12곳·페이지당 4곳과 구분한다.

이는 모든 본문을 빠짐없이 검색한 측정이 아니다. 결과 상한과 잠금·텍스트 상태 때문에 일부 페이지는 검색하지 않았다. 원본 보존은 상태와 파일 메타데이터 비교이며 모든 입력 파일의 전체 내용 해시 비교는 아니다. RSS는 특정 시점의 표본으로 최대 사용량을 뜻하지 않는다. 약 0.034초는 별도 검색을 시작해 실제 결과를 확인하고 취소한 관찰 전체 시간으로, 사용자 입력부터의 UI 반응 시간이나 개별 취소 호출 지연을 측정한 값은 아니다. 모델·서비스 검사이므로 실제 화면의 입력 반응성·native 전체 화면·장시간 사용 성능까지 검증했다고 해석하지 않는다.

재현 로그와 개인 정보를 제외한 집계는 로컬 `work/ember-gallery-search-20261005/`의 `search-tests.log`, `preview-tests.log`, `real-search-stress.log`, `real-search-report.json`, `validation.log`에 둔다. 임시 실문서 검사 소스는 같은 작업 폴더에 보관하고 상시 테스트 디렉터리에서는 제거했다. 개인 PDF 본문·파일 이름·세션 원문은 문서나 배포물에 포함하지 않는다.

### 실제 앱 확인

사용자가 열어 둔 두 워크스페이스와 26개 탭을 사용해 설치 앱에서 다음 흐름을 확인했다. 문서 이름이나 본문을 이 기록에 옮기지 않았다.

- 처음 워크스페이스의 PDF 12개에서 2개 문서가 있는 탭 그룹으로 범위를 좁혔다. 다른 워크스페이스를 선택하면 14개 카드가 나오고, 개별 탭을 선택하면 1개 카드가 남았다. 갤러리의 범위만 바꿀 때 배경의 활성 문서는 유지됐다.
- 개별 문서에서 `Swift`를 검색해 본문 결과 12곳을 확인하고, 더 보기로 처음 세 곳 외의 아홉 곳을 펼쳤다. 2페이지 결과를 선택하면 다른 워크스페이스의 해당 탭·2페이지로 이동하고 실제 PDF 본문에 노란 선택 강조가 표시됐다. 확인 후 해당 문서의 기존 10페이지로 복원했다.
- 모든 워크스페이스의 26개 탭 범위에서 `laser`를 검색하며 진행 표시를 확인했다. 검색 중지를 누른 뒤에도 이미 찾은 결과가 남았다.
- 개별 문서 범위에서 `power`를 검색해 12곳을 확인했다. 결과 카드의 발췌문과 해당 페이지 미리보기에서 앰버색 강조를 화면으로 확인했으며, 결과를 선택해 원래 워크스페이스의 문서·1페이지로 돌아왔다.

최종 설치본 재실행 후 두 번째 워크스페이스의 원래 활성 탭을 복원하고, 첫 번째 워크스페이스의 원래 문서 1페이지로 돌아간 다음 갤러리를 열어 새 선택 메뉴와 검색창을 확인했다. 이후 상태 비교에서 두 워크스페이스와 26개 탭의 식별자·순서·그룹·현재 페이지·선택 페이지·확대값 및 활성 워크스페이스는 유지됐다. 두 번째 워크스페이스의 활성 탭도 복원됐다. 다만 마지막 관찰에서는 첫 번째 워크스페이스의 활성 탭이 다른 기존 탭으로 바뀌어 있었고, 세 문서의 수직 스크롤 비율에는 각각 0.00015 미만의 차이가 있었다. 따라서 사용자 세션 전체가 완전히 동일하다고 기록하지 않는다. 최종 관찰 상태를 강제로 다시 바꾸지 않았다.

실제 UI에서 진행·중지·이동이 동작하는지는 확인했지만 GUI 응답 시간이나 GUI 실행 중 메모리를 계측하지는 않았다. 전체 화면 전환 및 모든 언어·창 크기·PDF 종류 조합을 검증한 결과도 아니다.

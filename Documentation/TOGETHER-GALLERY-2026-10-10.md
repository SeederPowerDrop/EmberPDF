# EmberPDF 0.9.0 build 40 — 함께 보기 갤러리와 패널 조절

기준일: 2026-10-10. build 39의 드래그 배치와 build 38의 Retina 미리보기 해상도를 유지한다.

## 문서 선택

- 함께 보기 설정은 갤러리로 시작하며 목록으로 전환할 수 있다. 카드에 PDF 미리보기, 이름, 워크스페이스·그룹·탭 순번과 페이지 정보를 표시한다.
- 현재 페이지 또는 첫 페이지(표지)를 미리 본다. 같은 창의 모든 워크스페이스를 대상으로 하며 워크스페이스 필터와 문서 이름·워크스페이스·그룹·탭 번호 검색을 제공한다.
- 선택한 문서는 필터와 독립적인 상단 목록에 남는다. 선택 해제·순서 변경과 최대 네 개 제한을 유지하며, 시작 버튼에서만 초안을 적용한다.
- 미리보기는 기존 직렬·취소 가능·크기 제한 서비스와 지연 그리드를 사용한다. 조회·검색·미리보기 때문에 휴면 탭이 활성화되거나 읽던 페이지가 바뀌지 않는다.
- 서로 다른 워크스페이스의 문서를 함께 고르고 저장·복원할 수 있다. 별도로 분리한 앱 창은 각 창의 문서 범위를 유지한다.

## 사이드바 조절

원인은 조절 중 반복되는 설정 전파와 렌더링, 화면 위치 재설정이었다. 기존 구분선의 전역 좌표와 드래그 종료 시 저장 방식은 이미 올바르게 구현되어 있어 유지했다.

- 미리보기 슬라이더·핀치 배율을 조절하는 동안에는 해당 화면의 임시 값만 갱신하고 종료 시 설정을 한 번 저장한다. 부모 패널의 최소 크기도 같은 임시 값으로 계산한다.
- 페이지 패널 구분선이나 배율을 조절하는 동안에는 기존 페이지 이미지를 늘려서 표시한다. 중간 크기의 PDF 래스터 생성을 보류하고, 놓으면 마지막 크기와 Retina 배율에 맞춰 갱신한다.
- 캐시에 정확히 일치하는 이미지는 즉시 사용한다. 같은 실제 픽셀 크기에 해당하는 미세한 변화는 새 요청을 만들지 않는다. 캐시·메모리 상한은 유지한다.
- 페이지 개요의 맞춤 보기에서는 크기 변경마다 두 개의 비동기 콜백을 예약하던 위치 재설정을 조절 종료 후로 합친다. 창 크기 변경은 120ms 동안 모으며, 조절 중 임시 배치 때문에 현재 페이지가 바뀌지 않도록 한다.
- 취소된 구분선 드래그, 탭 전환과 비활성화 때 임시 상태를 정리한다.

## 저장 검사에서 발견한 문제

분리된 창이 메인 창의 지연 저장보다 먼저 저장되면, 이전 메인 기록에 같은 탭 ID가 남을 수 있었다. 분리 창의 현재 탭 소유권을 우선해 이전 기록에서 탭·활성 탭·그룹 참조를 정리한다. 이로써 함께 보기 범위 정규화와 다음 실행의 창 복원이 중복 탭 기록에 영향을 받지 않는다.

## 검증

- 관련 XCTest **223개 통과, 실패 0개**: 갤러리·탭/워크스페이스·저장 복원·페이지 패널·개요·미리보기·메모리 정책·지역화 141개, 함께 보기·스크롤 동기화·앱 메뉴/편집 명령 82개.
- 새 검사는 메타데이터 필터, 같은 이름의 탭 정체성, 휴면 탭의 표지 미리보기, 다른 워크스페이스 연결 저장·복원과 창 소유권, 중간 크기 래스터 억제·취소 및 최종 Retina 해상도를 다룬다.
- 첫 통합 실행에서는 독일어 문구 검증과 새 저장 소유권 검사가 실패해 수정했다. PDFKit 화면 검사도 제한된 실행 환경에서 `PDFTileSurface`/`CFRelease(NULL)`로 종료되어 정상적인 네이티브 앱 접근 환경에서 다시 실행했고 82개 모두 통과했다.
- 최종 통과 로그: `work/together-build40/tests-core-pass.log`, `tests-comparison-native.log`. 정적 검사·패키지·설치 결과는 아래 산출물 기록을 따른다.

### 실제 앱 조작

별도 식별자의 QA 앱과 자체 생성한 A–E PDF 다섯 개를 사용했다. 사용자 문서는 수정하지 않았다.

1. E를 별도 이름의 Research 워크스페이스로 이동했다. 해당 워크스페이스에 PDF가 하나여도 함께 보기에서 다른 워크스페이스의 A–D를 확인했다.
2. 기본 갤러리에서 실제 미리보기와 Research/워크스페이스 1, 탭 순번을 확인했다. 선택 네 개 상태에서는 다섯 번째 문서가 비활성화됐다.
3. Research 이름 검색으로 결과가 한 개가 되어도 네 개의 선택은 유지됐다. 목록 전환과 워크스페이스 필터도 확인했다.
4. 필터 밖에 있는 E를 선택 상태로 둔 채 B/C를 선택 해제하고, E와 다른 워크스페이스의 A 두 문서를 함께 열었다.
5. 페이지 패널 구분선을 실제로 끌어 폭을 224pt에서 380pt로 변경했다. 현재 페이지가 유지되고 최종 미리보기가 표시됐다. 배율 제어의 100→105% 변경, 다시 열었을 때 값 유지와 100% 복귀도 확인했다.

입력 장치별 프레임 시간을 계측하거나 모든 대용량 스캔 PDF를 재시험한 결과는 아니다. 반복 작업을 줄이는 코드 경로와 동작을 검증했다.

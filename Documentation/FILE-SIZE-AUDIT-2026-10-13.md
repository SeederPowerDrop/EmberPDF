# PDF 편집 후 파일 크기 점검 — 2026-10-13

> 후속 build 62에서 호환 JPEG의 최초 삽입 용량 증가를 개선했습니다. 아래 수치는 수정 전 build 61의 기록이며, 변경 후 측정은 [사진 삽입 개선 기록](JPEG-INSERTION-2026-10-13.md)을 참고하세요.

EmberPDF build 61의 저장·편집 코드로 합성 PDF와 JPEG를 반복 편집하고, 실제 저장 파일을 다시 열어 크기와 내용을 검사했다. 이번 점검에서는 **반복 저장·본문 수정으로 파일이 기하급수적으로 커지는 현상은 재현되지 않았다. 사진 최초 삽입 시에는 원본 JPEG 대비 약 7.23배의 용량 증가를 확인했다.**

이번 작업은 감사와 회귀 테스트 추가이며, 앱의 압축·저장·편집 동작은 변경하지 않았다. 모든 PDF와 이미지 구조에 대한 보증은 아니며, 아래 결과는 이 환경에서 생성한 테스트 자료에 한정된다.

## 사진 최초 삽입이 커지는 이유

[BoundedImageLoader](../Sources/HwattakPDF/Services/BoundedImageLoader.swift)는 JPEG를 비트맵으로 읽고, [ImageStampAnnotation](../Sources/HwattakPDF/Services/ImageStampAnnotation.swift)은 잘린 영역만 담은 sRGB 비트맵을 PDFKit에 전달한다. 이 경로는 원본 JPEG의 압축 데이터를 그대로 보존하지 않는다.

측정한 1024×768 JPEG는 저장된 PDF에서 `/FlateDecode` 이미지로 바뀌었고, 그 이미지 스트림만 2,175,160바이트였다. 따라서 실제로 확인한 문제는 **사진 삽입 시 압축 표현이 바뀌어 처음 한 번 크게 증가하는 현상**이다. 사진의 압축률·내용에 따라 증가율은 달라진다. 반복 저장으로 매번 7배씩 커졌다는 뜻은 아니다.

## 코드와 검증 범위

[AtomicPDFWriter](../Sources/HwattakPDF/Services/AtomicPDFWriter.swift)는 새 임시 PDF를 검증한 뒤 목적지 파일을 교체한다. [PDFBodyTextEditor](../Sources/HwattakPDF/Services/PDFBodyTextEditor.swift)는 `FPDF_NO_INCREMENTAL`로 본문 변경 결과를 직렬화한다. 코드를 읽는 것만으로 PDFKit의 리소스 보존 동작을 보장할 수 없으므로, 반복 저장과 재개방을 포함한 검사를 추가했다.

추가한 7개 테스트는 다음 3개 클래스에 있으며, [배치 실행 스크립트](../scripts/run_test_batches.sh)에도 등록했다.

- [PDFMergeFileSizeTests](../Tests/HwattakPDFTests/PDFMergeFileSizeTests.swift): 반복 저장, 반복 PDF 추가, 일부 페이지 추출.
- [PDFBodyTextFileSizeTests](../Tests/HwattakPDFTests/PDFBodyTextFileSizeTests.swift): 반복 본문 수정, 반복 FreeText 수정, 압축 이미지가 있는 페이지의 본문 수정.
- [PDFImageFileSizeTests](../Tests/HwattakPDFTests/PDFImageFileSizeTests.swift): 사진 삽입, 반복 저장·크기 변경, 자르기, 삭제.

최종 실행은 **7개 통과, 실패 0**이며, 배치 스크립트의 `zsh -n` 문법 검사도 통과했다. 최종 실행 로그

최초 실행에서는 압축 이미지 테스트의 기본 렌더링 픽셀 비교 1개가 실패했다. 원본 이미지 데이터, 크기, 색 공간과 배치 행렬은 같았지만 저장 과정에서 이미지의 보간 힌트가 `/Interpolate true`로 바뀌어 색 띠 경계의 표본 추출 결과가 달라졌다. 최종 검사는 `CGContext.interpolationQuality = .none`으로 양쪽의 보간 조건을 고정하여 원본 픽셀과 배치가 정확히 보존되는지 확인한다. 디코딩된 이미지 바이트도 별도로 완전 일치를 검사하며, 기본 렌더러의 모든 픽셀이 언제나 같다는 보증으로 해석하지 않는다. 진단 로그

재현 명령:

```sh
EMBER_SIZE_AUDIT_DIRECTORY="$PWD/work/file-size-audit/final" \
  swift test --disable-sandbox --filter 'PDF(BodyText|Image|Merge)FileSizeTests'
```

원본 사용자 PDF는 변경하지 않았다. 합성 자료는 페이지별 고유 JPEG와 검색 가능한 표식을 포함하며, 사진 삽입 자료는 압축 변화가 드러나도록 질감이 있는 JPEG를 사용했다. 이미지 중복 제거, 다른 글꼴·색 공간, 외부 PDF 생성기의 특수 구조에 대한 추가 검증 여지는 남아 있다. 이번 결과는 파일 용량을 다루며, 편집 중 메모리나 복구 저장소 용량의 상한을 검증한 결과는 아니다.

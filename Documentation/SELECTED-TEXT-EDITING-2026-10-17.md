# 선택한 본문 편집과 스캔 PDF

대상 소스: **EmberPDF 0.9.0 (build 76)** · **2026-10-17**. 관련 테스트와 Release 패키지 검증 완료. 동시 작업 중인 설치 앱은 교체하지 않고 별도 실행본으로 제공한다.

사용자가 요청한 동작은 편집 모드에서 문장을 드래그하고 가T 버튼을 누른 다음, 그 문장 위에서 글자를 바꾸는 것이다. 기존 흐름은 드래그를 마치자마자 본문 편집을 시도했고, 명시적으로 버튼을 눌렀을 때 편집 대상을 찾지 못해도 새 글자 삽입 모드로 전환할 수 있었다.

## 편집 진입

- 드래그를 마치면 보통의 선택 범위를 유지한다. 가T를 누를 때 본문 편집을 연다.
- 가T의 접근성 이름과 도움말을 10개 언어에서 본문 편집으로 바꾼다.
- 실패한 명시적 본문 편집은 선택을 유지하고 오류를 알린다. 빈 입력 상자로 전환하지 않는다.
- 본문 입력기는 페이지의 원래 글자 위치에 놓인다. 드래그한 범위를 TextKit 선택으로 넘기고 키보드 포커스를 준다.
- 입력하면 처음 드래그한 글자만 바뀐다. 같은 PDF 텍스트 묶음의 앞뒤 글자도 편집기에 보일 수 있으며, 클릭·방향키로 커서를 옮겨 이어서 편집할 수 있다.
- 선택한 맨 위 줄을 화면 위에서 38% 위치로 한 번 이동한다. 확대율은 유지하며, 문서 가장자리는 가능한 스크롤 범위로 제한한다.
- Return은 줄 바꿈, ⌘Return은 적용, Esc는 취소다. 적용은 한 번의 실행 취소로 되돌린다.
- 텍스트를 선택하지 않고 본문 편집 도구로 빈 곳을 누르면 새 본문을 넣는다. 보기·학습 모드의 메모 도구와 기존 FreeText 주석 편집은 각각의 주석 동작을 유지한다.

## NEWTON 문서의 별도 원인

`NEWTON HIGHLIGHT 수학으로 보는 우주(Newton Highlight 132) (뉴턴프레스).pdf`는 Adobe Acrobat Paper Capture로 만든 스캔 PDF다. 21쪽 등은 원본 스캔 이미지와 보이지 않는 OCR 텍스트를 함께 담는다. 한글 OCR 글꼴에는 실제 글자 윤곽이 없어서 글자 높이가 0으로 보고되는 부분도 있다. 일반 PDF의 보이는 텍스트 객체만 바꾸는 기존 경로로는 화면의 스캔 글자가 바뀌지 않는다.

스캔 경로는 선택한 OCR 객체를 찾고 실제 이미지의 종이색과 글자 영역을 검사한다. 대응하는 OCR 객체를 제거한 뒤 원본 이미지에서 검사한 줄 영역을 벡터 클립으로 가리고, 종이색과 검색 가능한 PDF 본문을 넣는다. 원본 이미지는 다시 래스터화하지 않는다. FreeText 주석을 만들지 않으며 적용된 글자는 일반 본문 편집 경로로 다시 열 수 있다. 텍스트 층이 없는 스캔은 먼저 OCR 결과를 적용해야 선택할 수 있다.

OCR에 원래 인쇄 글꼴이 없으므로 대체 글꼴을 사용한다. 기존 OCR의 인식 오류를 임의로 교정하지 않는다. 글자 높이는 스캔의 실제 잉크 높이에 맞추고, 가로 진행 폭은 원래 줄의 폭을 기준으로 보정하지만 인쇄 글꼴의 모양까지 같게 재현하지는 않는다. 선택을 포함한 OCR 줄이 다시 조판되므로 같은 줄의 앞뒤 글자 모양도 달라질 수 있다.

스캔 편집은 밝고 균일한 배경 위의 수평 본문을 대상으로 한다. 글자 위치와 맞지 않는 그림·잉크가 있거나 배경·배치 검사를 통과하지 못하면 적용하지 않는다. 복잡한 수식의 조판, 회전된 스캔과 모든 OCR 구조를 지원하는 기능은 아니다. 입력이 검사된 스캔 영역을 넘으면 더 넓은 문장·문단을 선택하거나 글자 크기를 줄여야 한다. 워드처럼 다음 문단과 페이지까지 자동으로 밀어내는 문서 전체 재배치는 포함하지 않는다.

원본 스캔 이미지 데이터에는 수정 전 글자가 남아 있으므로 이 방식은 보안 삭제가 아니다. 본문 변경은 열린 문서에 실행 취소 가능한 편집으로 적용되며, 파일에는 저장할 때 반영된다.

## 보존 검사

- 하나의 OCR 객체 안에서 기준선이나 글자 사이 간격이 크게 달라지면 다른 줄·열까지 포함할 수 있으므로 거부한다.
- OCR 글자 위치로 설명되지 않는 잉크와 그림, 균일하지 않은 배경을 검사한다.
- OCR 내용을 전체 재생성하지 않는다. 원본 콘텐츠 스트림에서 선택된 텍스트 표시 명령만 제거하고, 나머지 이미지·OCR 문자 매핑과 리소스를 보존한다. 각 삭제 위치는 PDF 엔진의 접두 스트림 객체 수와 행렬로 교차 확인한다.
- 삭제 이후 남은 글자의 위치가 독립적으로 지정된 경우만 허용하며, OCR을 제거한 중간 PDF의 전체 렌더가 원본과 같은지도 확인한다.
- 새 글자의 실제 영역이 검사된 스캔 영역 안에 들어가는지 확인한다.
- PDFKit 기본 저장은 이 문서의 수정하지 않은 한글 OCR도 잃을 수 있다. 스캔 편집한 문서는 저장·자동 복구 시 PDFKit이 만든 목차·주석·페이지 구조를 유지하면서, 실제 페이지 콘텐츠와 폰트 리소스를 원본 그래프로 보존한다. 긴 목차는 재귀 대신 객체 큐로 처리한다.
- 페이지 원점 정규화는 검증된 공통 평행이동으로만 보정한다. 암호화·평탄화 등 별도 저장 옵션과 보존 경로를 섞지 않는다. 문서 그래프 보존 한도는 512 MiB·250,000개 객체다.
- 모든 변경은 분리된 페이지 복사본에서 준비한다. 실패 시 열린 원본 문서를 변경하지 않는다.

## 검증 기록

다른 채팅이 같은 프로젝트를 동시에 수정하므로 `work/selected-text76-source/`에 고정한 소스와 독립 빌드 디렉터리를 사용했다. 현재 공유 소스에 뒤이어 추가되는 build 77 변경과 이 패키지를 구분한다. 설치 앱 종료·교체와 수동 실행은 하지 않았다. 입력 화면 검증은 AppKit/PDFKit XCTest 창과 캡처를 사용했다.

- 최종 관련 XCTest: **340개 중 337개 통과, 3개 건너뜀, 실패 0개**. `work/native76-root/final-related-tests.log`. 본문·스캔 엔진, 실제 문서 입력, 실행 취소, 저장·복구, 글꼴·줄 간격, 읽기 색상, 선택·화면 위치, 정보 창을 포함한다. 건너뜀은 별도 실문서 디렉터리를 지정해야 하는 검사 1개와 macOS 15 PDFKit의 offscreen tile 해제 문제 때문에 비활성화된 화면 검사 2개다. NEWTON 실문서 검사는 환경 변수를 지정해 실제 실행했다.
- 추가 독립 문서 그래프 검사 **4개 통과**: 긴 목차 160개, 비영점 페이지 원점·주석·픽셀 보존, 호환되지 않는 변환 거부, 현재 자르기·크기·회전 보존. 마지막 항목은 최종 관련 XCTest 이후 추가됐으며 위 340개에 중복 합산하지 않았다. `work/page-content76-typecheck/tests-run.log`.

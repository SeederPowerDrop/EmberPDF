# PDF 본문 텍스트 편집 — 2026-10-07

> 버전: **0.9.0 (build 28) Developer Preview**
> 상태: 구현, 관련 자동 검사, 분리된 실제 앱의 수동 확인 및 로컬 패키지 검증 완료. 실제 교재 PDF와 타사 뷰어 검증은 아래에 별도로 남긴다.

## 해결하는 문제

이전에는 편집 모드에서도 선택한 본문을 바로 고칠 수 없었다. PDF 텍스트 도구는 FreeText 주석을 추가했고, 선택 영역의 시각적 교체도 원래 글자를 그대로 둔 덮개였다. 변경한 문구가 검색·복사에 반영되는 실제 본문 수정 요구를 충족하지 못했다.

이제 `PDFBodyTextEditor`가 PDFium으로 대상 텍스트 객체를 찾아 제거하고, CoreText가 만든 새 본문 텍스트를 기록한다. PDFKit은 화면 표시·검색·문서 상태를 계속 담당한다. 기존 주석 편집은 그대로 유지한다.

## 사용 방법

1. **편집** 모드에서 **PDF 텍스트**를 선택하고 고칠 본문을 클릭한다. **선택** 도구로 본문을 더블클릭하거나 글자를 선택한 뒤 **PDF 텍스트**를 눌러도 된다.
2. 입력창에 표시된 전체 내용을 확인한다. PDF에 저장된 하나의 텍스트 묶음이 대상이므로 드래그로 선택한 단어보다 범위가 넓을 수 있다.
3. 글자와 모양을 수정하고 `Return` 또는 `⌘Return`으로 적용한다. `Shift-Return`은 줄 바꿈, `Esc`는 취소다.
4. 입력 내용을 모두 지우고 적용하면 해당 텍스트 묶음을 삭제한다. PDF 텍스트 도구로 빈 곳을 클릭하면 검색·복사 가능한 새 본문을 추가한다.
5. `⌘Z`로 되돌릴 수 있다. 원본 파일은 저장할 때 변경한다.

텍스트가 없는 스캔 이미지에는 수정할 본문 객체가 없다. OCR로 만든 보이지 않는 텍스트도 현재 fill-only 편집 대상이 아니므로 이미지 글자 교정으로 사용할 수 없다. 빈 곳에 새 글자를 추가하는 것과 스캔 그림 속 글자를 바꾸는 것은 서로 다른 기능이다.

## 지원 범위

- 한 native text object 전체의 수정·삭제와 새 본문 텍스트 추가.
- 수평의 일반 fill-only 텍스트, 양의 균일 스케일, 편집기 범위인 6–144pt.
- 새 텍스트의 글꼴·크기·색상·정렬·배경 조절. CoreText로 글꼴과 Unicode 매핑을 포함해 검색·복사할 수 있는 콘텐츠를 생성한다.
- 원본 글꼴 이름에 대응하는 Mac 글꼴을 우선 사용하고, 없으면 serif·고정폭·굵기·기울임 특성을 반영한 대체 글꼴을 사용한다. 원본 embedded font subset의 외형을 그대로 재현하는 보장은 없다.
- 편집 페이지의 지원하는 단색 본문·도형은 PDFium이 해석한 RGBA 색으로 기록한다. 저장 후 재편집할 때 ICCBased 색 연산자가 누락되는 네이티브 엔진의 제한을 보완한다. 원본 ICC 프로파일의 의미를 그대로 유지하지는 않는다. CMYK와 별색 계열·패턴처럼 표시 색상 보존을 보장하기 어려운 페이지는 편집을 거부한다. 이미지 자원은 이 색상 변환 대상이 아니다.
- 기존 FreeText 및 과거 시각적 교체 주석은 기존 주석 편집 흐름으로 유지한다. 과거 덮개를 본문 수정으로 자동 전환하거나 그 아래 원문을 자동 삭제하지 않는다.

문단 전체의 자동 재흐름, 여러 객체에 걸친 임의 선택 범위만 치환하기, 회전·전단·반전·비균일 스케일·클리핑·특수 렌더링의 텍스트와 이미지 속 글자 편집은 지원하지 않는다. 기본값이 아닌 `/UserUnit`을 사용하는 페이지도 지원하지 않는다. 동일 페이지에서 같은 Form 스트림을 여러 번 사용하는 경우, 그 페이지의 중첩 Form 안 텍스트 편집은 다른 위치까지 바뀌지 않도록 거부한다. 공유하지 않는 중첩 Form은 대상의 뒤에 다른 그리기 객체가 없고 Form의 클리핑·투명도 상태를 안전하게 보존할 수 있을 때 지원한다. 새로 추가한 단일 텍스트 Form은 다시 편집할 수 있다. 긴 수정 내용은 페이지 안에서 줄을 바꿀 수 있으나 주변 문단·이미지를 밀어내지 않는다. 최종 글자가 페이지 밖으로 나가면 적용을 거부한다. 이때 글자 크기를 줄이거나 입력 내용을 짧게 고친 뒤 다시 적용할 수 있다.

중첩 Form 안의 대상을 편집할 때는 페이지의 Form 호출 전체를 추가로 검사한다. Form `/Group`이 있거나 `Normal`·`Compatible` 외의 blend mode 또는 blend mode 배열이 사용된 페이지는 중첩 대상의 편집을 거부한다. 이 조건과 공유 Form 조건은 중첩 대상에 적용하며, 페이지 최상위 텍스트 객체에는 나머지 보존 검사를 적용한다.

현재 네이티브 엔진이 콘텐츠를 다시 기록할 때 보존하지 못하는 패턴 색상, shading 그라데이션, inline image가 사용된 페이지는 편집을 거부한다. 지원하지 않는 soft mask·색상 transfer function, 기본값이 아닌 miter limit, Type3 등 지원 대상 밖의 글꼴, 글자를 클리핑 경로로 쓰는 렌더링 모드도 페이지 편집을 거부하는 조건이다. 일반 이미지 XObject는 유지한다. 이 검사는 고치려는 글자 외의 콘텐츠가 다시 기록되는 과정에서 달라지지 않도록 적용 전에 수행한다. 지원하지 않는 페이지도 기존 읽기·선택·주석 기능은 사용할 수 있다.

본문 객체를 바꾸는 기능이며 문서 전체의 숨은 데이터·다른 위치의 동일 문구·첨부·메타데이터를 제거하는 보안 redaction 기능은 아니다.

## 변경과 실패 처리

`PDFWorkspaceState`의 본문 초안은 원본 페이지 identity와 `PDFBodyTextTarget`을 함께 보관한다. 도구줄은 영역 선택이 도구 전환으로 사라지기 전에 본문 대상을 확보한다. 적용할 때 원본 객체의 텍스트와 위치를 다시 확인해 오래된 대상으로 편집하지 않는다.

엔진은 한 페이지의 분리된 스냅샷에서만 작업한다. PDFium이 결과 페이지를 생성하고 PDFKit이 다시 열 수 있어야 실제 문서의 페이지 교체로 진행한다. 실패한 경우 원본을 유지하고 오류를 표시한다. 성공한 수정만 문서 실행 취소 이력에 한 페이지 보관 비용으로 기록한다. 무변경 적용과 새 빈 초안 취소는 편집 이력을 만들지 않는다.

크기 초과 등으로 적용하지 못한 초안은 PDF가 아직 변경되지 않은 상태여도 저장·탭 닫기·탭 그룹 삭제·워크스페이스 삭제·창 닫기·앱 종료에서 보존한다. 저장할 변경이 없다고 보고하거나 초안을 버리고 종료하지 않는다. 사용자는 내용을 고쳐 다시 적용하거나 편집기의 취소로 명시적으로 버릴 수 있다. 별도 폐기 확인을 끝낸 작업공간 삭제 API는 해당 결정을 따른다.

PDFium handle은 서비스 호출 밖으로 전달하지 않는다. main actor에서 직렬로 접근하고, 다음 상한을 적용한다.

| 항목 | 상한 |
| --- | --- |
| 페이지 스냅샷 및 출력 | 64 MiB |
| 탐색하는 페이지 객체 | 50,000개 |
| 페이지 텍스트 추출 | 250,000자 |
| Form 탐색 깊이 | 16 |
| 입력 초안 | 32,768 grapheme, 1,048,576 UTF-16 code unit |

문서 권한과 모드 제한은 기존 capability 정책을 따르며, 잠긴 문서와 사용자 암호 권한의 문서에는 본문 변경을 적용하지 않는다.

## 검증

같은 build 28의 검색 후속 수정은 현재 페이지부터 순환 검색하며, 검색 중에도 결과·이전·다음 버튼을 사용할 수 있게 한다. `Enter`와 `Shift-Enter`는 모델의 `submitSearch`를 통해 같은 검색의 다음·이전 결과로 이동하고, 새 검색어일 때만 새 작업을 시작한다. 아직 찾지 못한 다음 결과 요청은 다음 실제 일치 항목이 발견될 때까지 보관한다. 결과 그룹은 페이지 번호순으로 다시 정렬하지 않고 검색한 순서를 유지한다. 도구줄의 검색 사이드바 버튼은 실제 표시 상태를 기준으로 열기·닫기와 접근성 상태를 바꾼다.

### 실제 앱 확인

사용자의 열린 문서와 저장되지 않은 변경에 영향을 주지 않도록 별도 앱 식별자를 가진 QA 앱에서 합성 문서로 확인했다.

- 8페이지 문서의 4페이지에서 검색을 시작해 첫 결과가 4페이지에 나타나고, Enter로 같은 페이지의 다음 결과와 5페이지로 이동하며 Shift-Enter로 되돌아가는 것을 확인했다. 검색 결과 패널을 닫았다 다시 열어도 선택한 결과를 유지했고, 페이지 그룹도 4페이지부터 표시됐다.
- 본문 `Original text`를 `본문 수정 성공`으로 바꾸어 적용·검색하고, 다시 편집기를 열었을 때 전체 한글 문구가 유지되는 것을 확인했다. 이를 `본문 다시 수정`으로 한 번 더 고쳐 사본을 저장했다.
- 한글 대체 글꼴 때문에 재편집 대상이 여러 객체로 나뉘던 문제를 수정했다. 선택한 글꼴이 전체 입력을 표시하지 못하면 전체 문자열을 표시할 수 있는 대체 글꼴을 우선 사용하며, 저장·재편집 회귀 검사도 통과했다.
- 수정 전후 합성 페이지를 렌더링해 이미지와 파란 도형이 유지되는 것을 확인했다. 반복 편집 시 색 공간 연산자가 사라지던 문제를 수정하고, 단색 보존과 지원하지 않는 색상 구조 거부를 자동 검사했다.
